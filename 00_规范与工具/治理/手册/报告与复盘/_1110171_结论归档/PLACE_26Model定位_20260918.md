## ⑤ 判定

**定位没有错。** 逐级核对：GLB 导出级 ✅（26/26 与源 bbox 比值 1.0000，无缩放）／节点变换级 ✅（pos_offset 单次、无 T/R/S 叠加）／父级级 ✅（挂 scene、每帧同步 `root.matrixWorld`、无双重变换）／单位与朝向 ✅（与武器同一空间、世界缩放 1.0）。

**用户看到的「巨块」由两件独立事实叠加造成，与定位无关：**
1. **尺寸本就与武器同量级甚至更大**：并集比武器宽 **2.47×**；单个 `H_m_流光` 长 9.80 vs 武器 8.63；16/26 比武器更厚；6 个单体即可包住整把武器；26 个又都堆在锚点附近。
2. **材质纯白且叠加**：**24/24 GLB `images = 0`（零贴图）** → 导出器在无 a/n/m 槽时只写 `baseColorFactor=[1,1,1,1] + metallicFactor=1 + roughnessFactor=1`（`export_glb.py:114-118`）；适配器当前 **`MODEL_BLEND='additive'`, `K=0.2`**，且 `transparent=true / depthWrite=false / DoubleSide`（adapter L48-49, L162-170）⇒ 26 片白色 additive 叠加 = 青白实心块。

**与给定线索的出入（均为实测，供更正）**
- 「26 个 GLB 加载 ok」**默认不可复现**：`effects.models_enabled` 未 true ⇒ 26/26 停在 `disabled_fail_closed`；`WikiSfxAdapter.models(true)` 返回 `true` 但**只翻 `group.visible`、不调 `loadModel`**（L537-542），`MODELS_ON` 又是构造期常量（L135）⇒ **必须 models(true) + 关开查看器重建适配器**才能加载 26/26（本次即如此取得数据）。属 API 缺陷。
- 「混合模式已从 additive → NormalBlending」**与实测不符**：当前 `MODEL_BLEND='additive'`、`MODEL_BLEND_K=0.2`。
- `attach.anchor` 实测 `[0.0279, 0.7798, -0.0855]`，非 `[0,0,1.4462]`。
- `.gim BoundingHalf≈0.3` 只是最小模型（八卦），非 26 个的代表值。

**unresolved**：① `ScaleStyle` 的语义（值为 null，无法判定）；② 源引擎是否本应用骨骼/挂点缩放把模型收敛到武器尺度（本数据无 BindBones*，无法判定）。
