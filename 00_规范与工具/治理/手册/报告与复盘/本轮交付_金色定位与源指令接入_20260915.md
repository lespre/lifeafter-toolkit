## ③ 源指令接入：已追到指令级，接入未验证（不冒充成功）

### 追到的两条缺失贡献（GBuffer 写出端 `02ac9f54` 族，反汇编字面证据）

```asm
393| sample_l_indexable(texturecube) r8, r8.xyzx, t4, s3, r1.x   ; ★ 采样 t_custom_ibl（= qiangpi.cube）
394| mul r1.x, r8.w, 16.0                                        ; ★ env.a × 16
395| mul r1.xyz, r1.xxx, r8.xyzx                                 ; ★ env.rgb × (env.a×16)
396| mul r1.xyz, r1.xyzx, r1.xyzx                                ; ★ 平方 → (env·a·16)²
397| min r8.xyz, r1.xyzx, 1.5                                    ; ★ clamp 1.5
400| mad r1.xyz, cb1[86].z, r8−r1, r1                             ; ★ 混合系数 cb1[86].z（值未追到）
401| mul r1.xyz, r1.xyzx, cb1[239].xxxx                          ; ★ × 环境亮度体系
418| lt r2.w, 0, cb1[286].w                                      ; ★ 开关
421| mul r5.xyz, r0.xyzx, (1−r3.x)                               ; r0 = BaseColor（469 行 o1.xyz=r0.xyzx 直证）
423| mul r5.xyz, r5.xyzx, cb1[286].xyzx                          ; ★ 以 cb1[286].rgb 给 BaseColor 着色（加法项）
429| mul o0.xyz, r1.xyzx, cb1[266].xxxx                          ; SV_Target0 = × u_hdr_luminance
```

- **贡献 A（环境项）**：源把环境采样按 `env.a×16 → 平方 → clamp 1.5 → 混合` 处理，与"直接把 env 当线性环境用"完全不同；这是**量级上的差异**（平方 + 16 倍），我此前完全没有这一项。
- **贡献 B（加法项）**：`BaseColor × (1−r3.x) × r3.w × cb1[286].rgb`，由 `cb1[286].w>0` 开关；材质宏列表里确有 `EMISSIVE_MODE`。**这是金色最可能的候选承载路径之一，但 `cb1[286].rgb` 的实际取值与 r3.x/r3.w 语义均未追到 → 只能标 `unresolved`，不得写成"金色来源已闭环"**。
