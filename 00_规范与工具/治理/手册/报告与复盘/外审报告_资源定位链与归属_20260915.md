
### 5.1′ THFB 结构（按成对字节核验重写；旧切分已作废）

**结构（对 14 组同名 THX/THH 逐字节比较得出）**
```
THX = 104B header + shared[count] × u32 + thx_tail[count] × 24B   ⇒ 104 + count×28
THH = 104B header + shared[count] × u32 + thh_tail[count] ×  4B   ⇒ 104 + count×8
count = u32 LE @96
```
尺寸公式虽然成立，但它只给总长度，**不能推出 AoS 单条记录布局**。

**验收结果**（`01拆包器本体/工具库/06_皮肤定位链/thfb_parse_v2.py --accept`）
| 验收项 | 结果 |
|---|---|
| 标准文件长度公式通过 | **176 / 178** ✓ |
| 同名 THX/THH 对总数 | 83 |
| shared 前缀逐字节一致 **且** tail 长度合格 | **82** ✓（不合格 0，跳过=异构 1） |
| `shared[-1] == count` | **176 / 176** ✓ |
| shared 文件内唯一率 | 100%（全部文件）✓ |
| shared 有序性 | 非升序、非降序（全部文件）✓ |
| thh_tail 文件内唯一率 | 100%（全部文件）✓ |
| shared 跨文件 | 总 197415，唯一 126545 → **重复率 35.9%** |
| thh_tail 跨文件 | 总 323800，唯一 132797 → **重复率 59.0%** |
| `thd\ui.thx` / `thd\ui.thh` | **异构，单独 fail-closed** ✗（count@96=1504912881；payload 1356940 / 4749260 与公式不符；0–124 内任何 4 字节对齐偏移都取不到整数 count）→ **不强套结构、不做容错截断** |

**24B tail 的内部形态（观察，不命名语义）**
样本（`thd\weapon.thx`，count=37）呈 **[u32 A][u32 B][u64 C][u64 D]**：
```
#0 A=0x00110026  B=0x00055604(=349700)   C/D = 3a be 0a 1f 4b 1e 8f a0 | 60 1d b9 7c 0f 6b 81 9c
#1 A=0x0011001b  B=0x00155604(=1398276)  C/D = ff d0 90 d8 ba 50 fe d2 | 03 0f 28 06 b0 a9 fd fa
#2 A=0x0011004a  B=0x00055604(=349700)   C/D = af aa e0 d5 31 87 f4 1f | 91 e8 15 3e e4 59 82 c7
```
- **`04 56 xx 00` 位于固定字段位（tail 内偏移 4–7）** ✓，且确实可表示**常见解码尺寸**
  （`0x00155604 = 1398276` = 1024² 带 mip 的 DDS；`0x00055604 = 349700` = 512² 带 mip）
  → 这是对旧版「位置不稳定、疑似 TLV」的**修正**：**位置稳定，且不是 TLV**。
  （注：在正确切分下该值**不在** shared/thh_tail 中；早前"字段位 0–6 全出现"的统计基于错误切分，作废。）
- A 形如 `0x00110000 | n`（n 为小整数）；C+D 为 16 字节值：文件内唯一 193675/197415，跨文件重复率 14.8%
  → **形态像 128 位摘要，但语义未命名**。
