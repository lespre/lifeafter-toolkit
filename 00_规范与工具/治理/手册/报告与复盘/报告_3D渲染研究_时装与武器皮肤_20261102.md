## 1. 数据与格式底座

- 还原树根：`01_索引与产物\41_还原树\pe\资源`。角色在 `character/`，武器在 `weapon/`，通用材质/场景容器在 `res/*.gpk/_未命名/*.c159`。
- NeoX 网格：`.mesh`（magic `34 80 c8 bb`，v4/v5）；时装 `.mesh` 子网格带材质序。
- 材质文档：时装 `.mtg`（magic `c1 59 41 0d`）；武器 `.c159`（通用容器，材质只是其中一种）。
- 贴图：`.ktx` 标准 KTX 1.1。**角色与武器实测都是 ETC2/EAC**：
  - 时装样本 `bag_m_3027_eu001n.ktx` → 0x9272（RG11 EAC，法线）；
  - 武器 4,617 张：`0x9274` RGB8 2,364 / `0x9278` RGBA8 EAC 1,391 / `0x9272` RG11 EAC 862；
  - 武器尺寸分布：512² 1,669、256² 1,201、128² 740、64² 593、1024² 62。
- `.gim/.gis`：模型挂接/动画，静态原型不消费。

> 旧结论「武器贴图 = 伪装 KTX + ASTC 8x8」**在本还原树样本上不成立**。若某些热更包确有 ASTC，应另立来源标记，不能写进通用管线。

## 2. 人物时装 3D 渲染

### 2.1 定位：目录三形态

| 形态 | 目录样式 | 部件组织 |
|---|---|---|
| 2021 分件 | `players2021/<prefix>_<f\|m>_<series>/` | b/h/bag 同目录，分件各自 mesh |
| 2025 分件 | `players2025/fas_<f\|m>_<series>/{var}/` | `var=<name>a` 分件，`<name>a_link` 合体 |
| 旧版 | `players/<...>` | 同上，命名更杂 |

定位器 `fashion_locate.py` 修复了 `players2025` 容器目录被排除的问题（新增容器正则 + 子目录二次解析）：索引从 2062 目录/831 系列 → **2276 目录/840 系列**。

### 2.2 `.mtg` 结构

- 名字表：`AnimParam … Version`；材料实例每条 `02 09 01` + `<name>\0`；着色器表 `shader\<x>.fx::TShader`。
- 恒等式：**材料数 = 着色器数 = 贴图块数 = 子网格数**（3715 body 21↔21、3640 18↔18、3223 4↔4）。
- 贴图块内间隔恒 6B、块间 100–650B；按文件序 1:1 映射，无需猜名字。

### 2.3 贴图角色与解析

| 槽 | 后缀 | 用途 |
|---|---|---|
| basecolor | `001a` | sRGB 基色 |
| param | `001m` / `s_m` / `1001b_m` | 参数图（G=粗糙/R=金属等，按着色器重排） |
| normal | `_h_001n` | 法线 |
| detail normal | `detail_normal_*` / `crystal_bump_*` | 细节法线（同 UV 近似合并进主法线后进 GLB） |
| IBL | `common\env_map\*.cube` | 环境 cube（还原树缺失，查看器改用程序化 studio IBL） |

解析器 `fashion_glb.py` 关键修复：`.mtg` 里写 `*_uvva.tga`，磁盘只有无后缀 `.ktx` ⇒ 增加去 `_uvva` 回退；同名兜底。最终 5 套 `a/n/m` **缺失贴图 = 0**。

### 2.4 材质 → PBR

- 直接映射：basecolor→baseColorTexture、param→metallic/roughness（按通道重排）、normal→normalTexture；detail normal 与主法线在切线空间近似合并（`normalize(n_main + 0.5·n_detail_xy)`）。
- alpha 走**着色器语义**而非 basecolor alpha 直方图：
  - `pbr_transparent*` → `BLEND`；
  - `silk/sss/subsurface` 且 alpha 低值占比 >5% → `BLEND`（3715 白纱 alpha 均值 0.68，OPAQUE 会变实体白塑）；
  - `hair/billboard` 且 alpha 有零 → `MASK` + `alphaCutoff=0.35`；
  - `uber_fx*` → `BLEND` + 查看器加法混合；
  - 其余 `OPAQUE`（角色 basecolor 的 alpha 常是遮罩通道，直接用来判 BLEND 会挖空布料）。
- metalness：param G 视作高光/金属遮罩，布料 `metallicFactor=0.12` 上限，`crystal/pearl` 保留全金属；无 param 图 → `metallic=0 / roughness=0.75` 兜底。
- `uber_mask_rim_diss` 是引擎侧边缘溶解特效壳（3245 甚至无底色图），导出时标记 `extras.hide=true`，查看器不渲染，避免白色/碎片外壳盖住衣服。

### 2.6 查看器

`02_wiki\web\fashion3d.html`：
- 读 `index.json` → 逐部件加载 GLB，保持源 **Y-up**（`rotate_x_deg=0`，按包围盒实测 body Y 0–16、hair 13.8–17.6），`Box3` 并集后 `group.position.sub(center)` 并按包围球算相机距离；
- **程序化 studio IBL**：canvas 生成等距柱状环境图 → `PMREMGenerator.fromEquirectangular` → `scene.environment`，配 3 盏方向光；没有 IBL 时 PBR 的金属/粗糙度会被压黑，贴图颜色出不来；
- 材质后处理：`envMapIntensity=1.15`；`BLEND` 层关闭 `depthWrite`；`extras.blend_mode=additive` 的 uber_fx 层改加法混合；`extras.hide` 的 rim_diss 壳不渲染；
- 部件显隐、白模切换（`userData.origMat` 备份还原）、自动旋转、复位、信息面板（系列/材质等级/缺失贴图）；
- `?id=<outfit_id>` 可直接打开指定套装；`window.__loaded / __fitted / __err` 供无头验证。
- 运行：`python -m http.server 8770 --bind 127.0.0.1`（在 `02_wiki\web` 下），打开 `/fashion3d.html`。
- 验证：5 套逐一无头截图，模型直立、有贴图颜色、半透层与特效层正常；`__loaded===2`、`__fitted===true`、无 `__err`。

### 2.7 时装残差（显式）

1. 第二 UV 集与 `uber_fx` 逐层参数仍未进 GLB；detail normal 已按同 UV 近似合并（非引擎的第二 UV 采样口径）；
2. IBL 未用真实 cube（`common/env_map` 在还原树中缺失），查看器改用程序化 studio 环境，非逐套匹配；
3. 3301 bag 仅 2 面（源网格如此，非导出丢失）；
4. `.mtg` 的 RenderStates（CullBack/AlphaRef 等）未逐项映射，alpha 仅按着色器粗分；
5. 贴图 1024 使 3715 单套 body 达 24.81 MB，网页首次加载偏重（可按需回落到 768 档）。

## 3. 武器皮肤 3D 渲染

### 3.1 素材链

```
行（item.id） → model_path（weapon/skin/skin_XXXX_YYY/skin_XXXX_YYY.gim）
             → 材质 .c159（res/weapon.gpk，条目自述 gim 与 tga 路径）
             → textures/*.ktx（本还原树已含，ASTC/ETC 见 §1）
```

- `weapon_skin_static_candidates_v01.json` 118 条静态记录可做 `item ↔ skin` 锚点（如 1110141→skin_2003_020）。
- 材质 c159 与子网格绑定另有 `.c159` 站（`Sub0→skim_0 …`），029 已由 `003997.c159` 直证。

### 3.2 c159 判类

`c159_pair.classify_c159()`：**`b'AnimParam\x00'` 存在 ⇒ material**；否则按首标识符（NeoX/Lod/…）或标记串判 scene/gis/anim。本次普查：

- `weapon.gpk` 2,098 + `res.gpk` 219 = **2,317 个 c159**；
- 材质 **1,896**（81.8%）；unknown 420；解析失败 1。

> 不能在容器原始字节里搜文件名——条目压缩；本次按**解包后的还原树**直读，路径 `res/weapon.gpk/_未命名/NNNNNNNN.c159` 与旧文档的 `003996.c159` 编号体系不同，属版本漂移。

### 3.3 跨皮肤普查（本次新增证据）

扫描 96 个 skin 号、119 份含皮肤的材质文档：

| 项 | 结果 |
|---|---|
| 材质数分布（每文档） | 0:7（未识别出 `skim_/skin_` 材料名）/ 1:33 / 2:36 / 3:16 / 4:11 / 5:10 / 6:2 / 7:2 / 8:1 / 9:1 |
| 着色器（材料实例） | pbr_weapon 141、pbr_default 70、pbr_crystal 31、pbr_clear_coat 11、pbr_subsurface 8、pbr_transparent 8、uber_fx_common 5、pearl_billboard 3、fur_v2_transparent 3、fx_liquid 3 |
| 声明 cube 的文档 | **37/119**（45 次声明，单文档可多 cube） |
| cube 频次（皮肤子集） | car_studio01 14、qiangpi 10、glazed_patio 7、glazed_patio2 3、industrial_pipe… 2、over_the_clouds 2、fashion_qiangpi 1、corsica_beach 1、jiayuan02a 1、indoor 1、bonifacio_street 1、login27_cube 1、basement_boxing_ring 1 |
| cube 频次（全库 1,896 材质文档） | car_studio01 15、qiangpi 15、glazed_patio 11、glazed_patio2 3、industrial_pipe… 2、over_the_clouds 2，其余各 1 |
| 含晶体着色器 | 22 份文档 |
| 逐材质数值配对成功 | 72/119（`c159_pair_v4` ordered-1:1；失败原因是材料数≠有效槽位组数或晶体数≠数值块数，fail-closed） |

结论：**皮肤是多材质拼装**，一套皮肤里同时存在 `pbr_weapon`（金属主体）+ `pbr_crystal`（宝石）+ 透明/珍珠/毛发等层；统一渲染器必须按材料逐个选链，不能按皮肤一刀切。

### 3.4 参数表与槽位

- 名字表三段：组件（AnimParam…TransparentMode）→ 参数（`t_*` 贴图槽 + `u_*` 数值/颜色槽）→ RenderStates（AlphaRef/AlphaVal/Ambient/CullBack/Diffuse/Emissive/Key/LightingEnable/MaterialCount/Name/Power/Specular/SpecularEnable/Speed/TechName/TransparentMode）。
- 数值块条目 `[01 00 01 13][type][payload]`，`type 01=str / 02=i32 / 05=f32 / 06=f32[n]`；**正向 1:1**：条目[k]↔组内数值槽[k]（字符串/宏槽不消耗）。
- 颜色槽固定 `f32[4]`，i32 开关与 f32 标量混排，故必须按类型校验，不能按名字猜。
- 029（`003996.c159`，LOD1）实证：材料1 19 条、材料2 18 条，宝石红 `u_crystal_color=(0.2431,0,0,1)`；LOD0（`004008.c159`）逐字节一致。

本次跨皮肤抽样补充：晶体材料的参数集合与 029 同族（`u_crystal_color / u_crystal_metallic / u_crystal_specular / u_caustic_* / u_refraction_* / u_subsurface_color`），个别皮肤改名为 `u_color_a / u_crystal_roughness / u_emissive_fresnel_inverse`（1012 系），说明**参数表随皮肤版本演化，解析器必须按名字而非固定偏移**。

| 槽 | 命名 | 说明 |
|---|---|---|
| 基色 | `<skin>001a` | sRGB |

| 折射 | `t_refraction_tex` / `t_reflection_tex` / `t_caustic_tex` | 晶体专用 |

### 3.6 IBL 链（与环境反射）

源侧（汇编级，见 `ENV_IBL_spec_1110171_1110177_20260919.md`）：

```text
R  = reflect(-V, N)
若 rotate: x' = cosθ·Rx + sinθ·Rz, z' = -sinθ·Rx + cosθ·Rz   (θ=u_rotate_angle)
LOD = 5 + 1.2·log2(max(rough, 0.0019))
S  = sample_cube(R, LOD)          // UNORM, 不 sRGB, ClampToEdge
C  = (S.rgb·S.a·16)²              // RGBM
C  = min(C, 1.5)
C  = lerp(C, min(C,1.5)·0.299805, sat(u_lightmap_factor))
out = C·u_cube_brightness·u_env_day2night_exposure
```

- `u_rotate_angle` 晶体在 `cb0[7].w`（材质级 @124）；武器 PS 在 `cb0[4].x`；`u_cube_brightness` 在 `cb0[8].x`（@128）。
- 现状链只消费 uniform 默认值：材质级 `cube_brightness/rotate_angle` **未从 c159/viewer.json 读取**；`uIblScale` 默认 0.25 自述「照抄 lab，无拟合」。
- 1110171 的 prim2 声明 `car_studio01` 却绑 `fashion_qiangpi` —— 本次普查显示 `fashion_qiangpi` **全库仅 1110177 一次声明**，因此这不是普遍规律，而是单例绑定错误（环境项约低 1.24×）。
- 作者 mip（8 级 128→1）未被消费，链用 GPU 自动 mip；两者 mean|ΔRGB| 4.35–33.26（qiangpi），源 LOD 内容不同。

### 3.7 贴图格式（修正）

见 §1：4,617 张武器 KTX 全部标准 KTX 1.1 ETC2/EAC，`texture2ddecoder` 可直接解，**不需要 astcenc**。若未来遇到非 KTX 1.1 头（`glType/glFormat=0` 且 internalFormat 为 ASTC），再按来源分流。

### 3.8 已知链路差距（沿用审计结论）

| # | 缺口 | 影响 |
|---|---|---|
| 1 | 材质级 `u_cube_brightness` 生产不消费 | prim 环境辐射按 1.0，非 0.71/2.74 |
| 2 | 材质级 `u_rotate_angle` 无读取路径 | 高光象限偏移 149–177° |
| 3 | 作者 mip 不消费 | LOD 采样内容与源不同 |
| 4 | `u_lightmap_factor` 值未取 | 分支默认 0，不生效 |
| 5 | `u_env_day2night_exposure` 硬编 0.25 | 整体环境量级无源依据 |
| 6 | 晶体 F0 用 three 的 0.04 起点 | 金属度 0 时镜面项约为源一半 |
