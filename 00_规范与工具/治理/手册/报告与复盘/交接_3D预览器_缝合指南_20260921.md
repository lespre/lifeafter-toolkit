## 2. 运行前置（最容易被忽略、也最容易踩坑）

1. **必须 HTTP**：`fetch()` 读 `viewer.json` / `neox_material.json` / `effects.json` / `*.glb`，`file://` 会被同源策略拦（origin=null）。→ 内嵌一个只绑 `127.0.0.1`、只读、指向 wiki 目录的**本地 HTTP 服务**（可打包成 sidecar 进程，或在内核里用自定义 scheme + 正确 MIME）。
2. **MIME 要齐**：`.js→text/javascript`、`.json→application/json`、`.glb→model/gltf-binary`、`.png→image/png`、`.dds→image/vnd-ms.dds`（或 `application/octet-stream`）、`.spr/.sfx/.mesh/.gim→application/octet-stream`。
3. **WebGL2**：需要可用的 GPU/ANGLE；若目标环境无独显，准备软件渲染回退（Chromium 启动参数 `--enable-unsafe-swiftshader`）并接受降帧。
4. **缓存键纪律（本项目内部约定，务必照办）**：`board.html` 里每个 `<script src="x.js?v=<sha256[:12]">` 的 `?v=` **必须等于该文件 sha256 的前 12 位**；否则浏览器用旧缓存，会出现"改了看不到"。
5. **不要另起第二个服务**：同一端口只能有一个；重复起会互相抢。

**只读调试/验收钩子（宿主可用来做自检）**

| 钩子 | 用途 |

## 5. 缝合方式（三选一）

**方案 A（推荐，最省事）**：把 `08Lifeafter wiki` 整个目录作为只读资源随 exe 分发，内嵌 `tools/wiki_server.py`（纯标准库）或等价的 C 服务，绑 `127.0.0.1` 随机端口，内核窗口加载 `http://127.0.0.1:<port>/board.html?b=weapon_skin_sfx_text_sources&view=wiki`；或自建最小宿主页（见 §7）直接调 `open()`。

**方案 B**：自绘内核注册自定义 scheme（如 `app://`），在协议处理器里做：路径映射 + MIME + **Range 支持**（GLB/PNG 较大，缺 Range 可能失败）。

**方案 C**：Electron/Tauri/nw.js —— 用其内建静态服务或 `protocol.handle`；注意关闭 `webSecurity` 不是好做法，**正确做法是提供服务**。

**不要做**：直接 `file://` 打开 `board.html`；把 `three` 换成别的版本（本工程按 **r180** 的 `Sprite/Material` 语义与 `metalnessMap.B / roughnessMap.G` 通道取值实现，换版本会静默错色）。

## 6. 必须保留的诚实标注（**不要美化、不要删**）

这套预览器在多处**明确区分"源数据"与"近似/自造"**，缝进 exe 后请保留这些字段与文案；否则会误导使用者以为一切来自游戏源数据：

| 项 | 位于 | 含义 |
|---|---|---|
| `fidelity.direct_light = "approximate_direct_lighting"` | `viewer.json` | 直接光的**数值是手填的**（游戏里该值由运行时 cbuffer 每帧填，静态数据读不到；字段位置已字节级定证） |
| `lighting_approx.enabled=true, intensity=4.0` | `viewer.json` | **用户授权的手填全局光**，用于提亮；`enabled:false` 一键回纯源态 |
| `cube_default_selection` | `viewer.json` | 默认环境 cube 是**产品选择**（`fidelity:"not_source_determined"`）；源侧无选择器。生效值由 `neox_material.json` 的 `t_custom_ibl` 决定，**该键请保持空串**（填名会打断 IBL，见 §8） |
| `weapon_skin_cubes_custom.js` 的 3 项 | `data/media/` | **自造**环境 cube（`self_authored_approximate`），非游戏资产；只能作为可选对照，**不得作默认** |
| `emissive_source.tier = "source_present_value_unreadable"` | `viewer.json` | 源值真实存在（`001348.c159@4198 = 0.7`）但运行时排列绑定未定证 |
| `neox_material.json` 的 `missing[]` | 材质清单 | 未随包发布的贴图：**一律 unresolved、零顶替**（不许拿别的图冒充） |

**体积/版权注意**：`assets/3d/weapon_skin/**` 与 `_shared/**` 是**游戏资产**（从《明日之后》/《LifeAfter》包体解出）。对外分发请自行确认授权，本工程只做技术交接、不授予再分发权。

## 9. 已知缺陷与近似（交接时必须一起说清）

| 类别 | 内容 |
|---|---|
| **已修** | ① 武器金属发黑：默认环境 cube 换 `night_clearsky02`，金属区 `dark% 75.37% → 1.2%`<br>② 特效"整层不画"：`particle_radius_to_world=1.0` 只写在 `effects.json`、而适配器读 `viewer.json.effects` ⇒ 补键后真粒子像素 **6 → 241–261 px**<br>③ "奇怪正方体"：粒子池漏回填贴图 ⇒ `map=null` 实心方块；已补回填 + fail-closed（无图集不画） |
| **未解（已定性，不再试参）** | ① **金色饰件不亮**：自发光只能提亮/去饱和，造不出金色像素；② **高光峰不足**：源 GI 项（`×2.761966 × u_cube_brightness`）已实现，但按 three 语义对 `metalness=1` 纹素零贡献；③ **泛光**：源有 `BloomThreshold/Intensity` 通道，但**值全在运行时 cbuffer**，静态不可得；④ 两条 `effect\textures\glow\*.tga` unresolved（零顶替） |
| **已知接口级缺陷（已登记未修）** | ① `cube_default_selection.cube` **填 cube 名会打断 IBL**（`__cubeAB` 预置纹理缓存却不登记 `__iblGate` ⇒ 5/5 prim `ibl_pending`）⇒ **保持空串**；想启用"产品默认入口"需改 viewer.js<br>② `WikiSfxAdapter.sprites(false)` **关不掉粒子层**（tick 的 systems 循环缺门）<br>③ 池内粒子共用同一 Texture 对象 ⇒ 每 tick 最后一个粒子写的 `repeat/offset` 覆盖全部<br>④ 粒子**跨 loop 边界不续存**（源 loop=1.0s、lifespan 1.0–1.5s）<br>⑤ `model_unit_scale` 只在 `effects.json`、`viewer.json.effects` 缺键（若开 Model 门几何会回落常量 0.1） |
| **测量工具本身的已知问题** | `accept_fx_follow_20260920.py` 的 A1/A2 对"单粒子层（~210 px）"无判别力；其 B 项会调 `models(true)` 打开 12 个 Model 门（属非默认态、与红线相悖）；固定 profile 目录会产生"武器没画出来"的假读数。**正在修口径**，勿把它的单次 PASS/FAIL 当结论 |
