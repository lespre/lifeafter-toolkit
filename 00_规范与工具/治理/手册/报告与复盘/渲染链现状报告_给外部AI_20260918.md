## ⚠️ 勘误（2026-09-18 晚，第三名分析员复核后）

**本报告 §2.3 与 §2.4/§4.3 中"LOD 公式不同型""金属度来源不同"两条结论已作废。** 
根因：第一名分析员**漏了 L330 对 `r1.w` 的覆盖**（`mul r1.w, r5.y, r5.y`，`r5.y = ParamMap.A`），
把 L335 的 `mul_sat r1.w, r1.w, cb0[4].z` 误判成金属度。
本报告使用的追踪器 `dxbc_dataflow.py` 是**线性前向扫描、不做分量覆盖检查**，正是它掩盖了这个错误
（对 `335 r1.w` 它返回"未找到写入"）。

**修正后的源公式（第三名分析员，逐行核对 L307-420 + deferred 变体）**：

```
metal = sat(ParamMap.G)                                    // 金属度
rough = clamp(ParamMap.R, 0.02, 1)                          // 粗糙度
spec  = sat( lerp(ParamMap.A⁴, 1, sat(nv²-0.3)) * u_specular )   // 介电高光强度（非金属度）
F0    = metal*base + spec*0.079956*(1-metal)
diff  = base*(1-metal)
LOD   = 5 + 1.2*log2(rough)                                   // t3 立方图
```

**⇒ 我方实现与源在以下各项完全一致**（这是本轮最重要的正面结论）：

| 项 | 源 | 我们（three） | 判定 |
|---|---|---|---|
| 金属度 | `ParamMap.G` | `param_repack.B`（= 源 `_m.G`）→ `metalnessMap.b` | ✅ 一致 |
| 粗糙度 | `ParamMap.R` | `param_repack.G`（= 源 `_m.R`）→ `roughnessMap.g` | ✅ 一致 |
| 立方图 LOD | `5 + 1.2·log2(rough)` | `5.0 + 1.2*log2(rough)` | ✅ 一致 |
| RGBM 解码 | `(S.rgb·S.a·16)²` | `pow(sm.rgb*sm.a*16, 2)` | ✅ 同型 |
| lightmap lerp | `lerp(C, min(C,1.5)·0.299805, sat(u_lightmap_factor))` | `uIblMix` 同式 | ✅ 同型 |

另：`cb0[4].z = u_specular`（NeoxUBOLocal offset **72**，四点互验）。
⚠️ `_known_loop/dxbc_cb_groups.json` 是**另一套布局**（rotate_angle@124、无 u_specular），**不能用来命名**。

## 2. 【本轮核心产出】源 shader 的数据流（已证实）

### 2.1 资源绑定表（来自 DXBC RDEF，asm L238-245，非推断）

```
t0 = Tex0                  texture2d
t1 = NormalMap             texture2d
t2 = ParamMap              texture2d
t3 = t_custom_ibl          texturecube
t4 = t_real_clustered_map  texture3d
t5 = ShadowMap             texture2darray
t6 = t_terrain_heightmap_shadow
t7 = t_cloud_shadow_noise  texture2d
```

### 2.2 输出合成（以 `pbr_weapon` PS 为例，`o0.xyz` 四项之和）

```
o0.xyz = [ IBL + 太阳直射×云影 + 簇光漫反 + 环境/雾基项 ] × cb1[266].x(场景曝光)
```

| 项 | 来源 | 备注 |
|---|---|---|
| **IBL** | `t3` cube → `r5.xzw × r1.w` | 见 2.3 |
| 太阳直射×云影 | `r9.xyz` | 云影 `t7` 只调制这一路 |
| 簇光漫反 | `r11.xyw` / `r14` | 灯表来自 `t4`（3D 簇查找图），**t4 的纹理值本身不进颜色**，只决定灯数与起点 |
| 环境/雾基项 | `r3.xyz` | |

### 2.3 IBL 通路（与我们的实现逐项对照）

```glsl
// 源（已从 asm 逐指令还原）
T    = tex2D(ParamMap, uv)                     // swizzle 后：r5.x=T.g  r5.y=T.a  r5.z=T.r  r5.w=T.b
lod  = 6.0 - 1.2*log2(clamp(T.r, 0.019989, 1)) // ⚠ 用的是 ParamMap.R
S    = cube.SampleLevel(t_custom_ibl, reflectDir, lod)
C    = (S.rgb * S.a * 16.0)²                   // RGBM 解码
C_w  = lerp(C, min(C,1.5)*0.299805, saturate(u_lightmap_factor))   // cb1[86].z
C_e  = C_w * u_env_day2night_exposure * r7.xyz // cb1[239].x ；**r7.xyz = 反照率色**
k    = lerp(saturate(cb0[4].z * 0.1212), 1, smoothstep(sat(5*clamp(NdotV,-0.3,1)-0.5)))
IBL  = k * C_e
```
**⇒ 与我们的 `getIBLRadiance` 覆写对比**：RGBM 解码（`pow(sm.rgb*sm.a*16,2)`）与 lightmap lerp（`uIblMix`）**完全同型** ✓；但 **lod 公式不同**、且**源把环境项乘了反照率色 `r7.xyz`，而我们的口径禁止乘**。

### 2.4 金属度 / F0

```glsl
metal = saturate(ParamMap.G)                   // 金属度（L341 mov_sat r5.xy → L343/L346 插值因子）
rough = clamp(ParamMap.R, 0.02, 1)             // 粗糙度（L339/340 → 立方图 LOD）
spec  = saturate( lerp(ParamMap.A^4, 1, sat(nv^2-0.3)) * u_specular )   // 介电高光强度
F0    = metal*baseColor + spec*0.079956*(1-metal)
```
**⇒ 与我们的实现对比**：金属度/粗糙度均来自 `ParamMap` 的 G/R 通道，**与我们的 `param_repack` 映射一致** ✓
（勘误：曾误判金属度来自 `NormalMap.a`，见顶部）

### 2.5 其他资源的角色（已定性）

- `t7` = **云影透过率**：UV 是世界方向投影到太阳基（**非屏幕空间**，已排除 SSAO），只调制太阳直射+镜面
- `t4` = **簇光查找图**（`cb3` 里 `u_cluster_point_list[64]`/`u_cluster_spot_list[96]`/`u_cluster_light_indices[500]` 均被使用；`u_vlm_*`/`u_fog_*` 全标 `[unused]`）⇒ **t4 的纹理值不进颜色**，只定灯数/索引
- 全片唯一真屏幕空间采样是 `t5`（ShadowMap 4-tap）

## 4. 三处**相互矛盾**的证据（这是最需要外部判断的部分）

### 4.1 `Tex0` 的文件身份：**unresolved**（不得据命名/外观推定）

**判定基准（用户明令）**：
- **RDEF 只证明槽位/寄存器，不证明物理文件路径** —— 不能由 `Tex0→t0` 推出"该绑哪张 png"
- **贴图外观与命名规则不构成绑定直证** —— 不得据"哪张看起来像 albedo"或 `001b_m → Tex0` 的命名规则选图
- **"不来自路径块"尚未成立** —— 该结论基于当前的块解析，而**块解析本身未复核**

**因此：文件身份保持 `unresolved`。** 下一轮需先做三件事，再谈绑定：
1. **复核 c159 的块解析**（当前块边界用路径间字节间隔 gap=410 推断，方法本身需再验）
2. **核实槽位与路径的对应关系**（是否真的按序、是否有版本差异）
3. **核对资产版本**（GPK 条目与逻辑路径是否同一版本的同批资源）

**禁止**：据此宣布"存在全局默认绑定"。

### 4.2 环境项：我们**缺少源的 BRDF 权重**（原表述"源把环境项乘了反照率"已作废）

**原表述错误**。经逐分量核对（asm L339-360，无覆盖），`r7.xyz` **不是反照率色**，而是
**由 roughness / NdotV / F0 计算出的环境 BRDF 权重**：

```glsl
rough = clamp(ParamMap.R, 0.019989, 1)
c0 = 1.0 - rough                              // r7.x
c1 = 0.04248  - rough*0.027496                // r7.y
c2 = 1.039062 - rough*0.571777                // r7.z
c3 = rough*0.021988 - 0.039978                // r7.w
t0 = min( (1-rough)^2, exp(-9.28*saturate(NdotV+1e-5)) )
t  = t0*(1-rough) + c1
A  = -1.04*t + c2
B  =  1.04*t + c3
envW = max( F0*A + saturate(F0.y*50)*B, 0 )   // ← 这才是乘到环境辐射上的量
// L392: env = envW * (RGBM解码 × lightmap_lerp × u_env_day2night_exposure)
```

**⇒ 正确目标（用户定版）**：
> 把这段**源环境权重**替换掉对应的 **Three 环境镜面权重**。
> **不能**放进 radiance 之后又让 Three 的 BRDF 再乘一次；
> **不能**改成裸 `env×albedo`；**不能**直接叠到最终屏幕颜色。

**当前实现的问题**：我们的 `getIBLRadiance` 只交 radiance，随后**由 Three 自己的环境镜面 BRDF（`EnvBRDFApprox` / GGX）去乘** ——
即**用的是 Three 的权重，不是源的权重**。这正是"编译成功、7/7 应用成功"**不等于源语义正确**的地方。

**状态：本轮未实现**（见 §6 的下一轮交付约定）。

### 4.3 ~~金属度的来源不同~~ → **已撤销（见顶部勘误）**

原写「源用 `saturate(NormalMap.a × cb0[4].z)`，我们用 ParamMap，来源不同」——**错误**。
实际源的金属度 = `sat(ParamMap.G)`，**与我们的 `param_repack` 映射完全一致** ✓
