# 拆包器 CLI 对标（2026-10-22）

对标对象：`repak`（UE pak）、`u4pak`、`AssetStudioModCLI`（Unity）、`QuickBMS`（脚本驱动）。

## 一、别人的 CLI 长什么样

### repak（Rust，UE .pak）

```
repak [OPTIONS] <COMMAND>
  info       Print .pak info
  list       List .pak files
  hash-list  List + SHA256（找版本差异）
  unpack     Unpack .pak
  pack       Pack directory
  get        Reads a single file to stdout
Options: -a/--aes-key <key>（hex 或 base64）
```

特点：**动词极简**，六个命令覆盖"看/列/取/解/打"；`--include` 通配过滤；`-v/--quiet`；路径穿越防护。

### u4pak

```
u4pak <info|list|check|unpack|pack|mount>
```

额外支持把参数写进 `.u4pak` 文件（Windows 双击即可跑）。

### AssetStudioModCLI（Unity）

```
AssetStudioModCLI <输入> [-m extract|export|exportRaw|dump|info|live2d|animator]
                        [-t tex2d,sprite,audio,...]  ← 资产类型
                        [-g none|type|container|fileName]  ← 分组方式
                        [-o 输出目录] [-r 覆盖]
                        [--filter-by-name 文本] [--filter-by-container]
                        [--filter-with-regex] [--log-level]
```

特点：**模式 + 类型 + 过滤器**三段式；导出结构可配置；JSON/XML 资产清单。

### QuickBMS

```
quickbms [-l] [-o] [-f 过滤] script.bms input output
```

脚本驱动：格式逻辑写在 `.bms`，CLI 只负责"跑脚本"。

## 二、我们现在的 CLI

```
la.py
  doctor / status / index / find / locate
  info(新) / list(新) / img / tables
  board / web / hotfix / spine / npk / watch / tool
```

## 三、逐项对标

| 维度 | repak | u4pak | AssetStudioMod | QuickBMS | 我们 |
|---|---|---|---|---|---|
| 看包信息 | `info` | `info` | `-m info` | `-l` | **`info`（新加）** |
| 列条目 | `list` | `list` | `-m dump` | `-l` | **`list`（新加，支持 --filter/--json）** |
| 按名过滤 | `--include` | — | `--filter-by-name` + regex | `-f` | **`--filter` 通配（新加）** |
| 单条取内容 | `get`（stdout） | — | — | — | `locate`（出元信息，未落盘） |
| 批量导出 | `unpack` | `unpack` | `-m export` | 脚本 | `img export` / `board run` |
| 分组/命名 | `--strip-prefix` | — | `-g` / `-f` | 脚本 | 固定（板块自定） |
| 加密参数 | `-a/--aes-key` | — | — | 脚本 | 内置（NPK 已在代码里） |
| 机器可读输出 | — | — | `--export-asset-list xml` | — | `find --json`、`list --json` |
| 覆盖策略 | 默认覆盖 | — | `-r` 开关 | `-o` | 默认覆盖 |
| 危险路径防护 | ✅ | ✅ | — | — | 输出目录固定，不拼用户路径 |
| 脚本/插件扩展 | — | `.u4pak` | — | ✅ `.bms` | `board run <py>` + `tool` 逃生舱 |

## 四、结论

**我们已经对齐的**：`info` / `list` / `find`（双源）/ `img export` / 批量构建。
**比他们强的**：

- `find` 一次给出 **PE + PC 双源落点**（他们只有单容器）
- `board` 把"取数 → 板块 → 校验 → 发布"串成一条链（他们只到导出文件）
- `tool` 逃生舱保留 43 个底层子命令，不牺牲深度

**还差的**：

| 缺口 | 对标 | 建议 |
|---|---|---|
| `get` 单条直接输出到 stdout | repak | `la.py get <包> <行> [--out -]` |
| `--filter` 正则 | AssetStudio | `list --filter-re` |
| 全局 `--json` | AssetStudio | `info/locate/img` 都补 `--json` |
| `-v/--quiet` | repak | 统一日志级别 |
| 剧本化批量 | QuickBMS | `la.py run <脚本.py>`（board run 的泛化） |

## 五、本轮已落地

```
la.py info <包> [--layer PE|PC]          容器条目数 / 名字覆盖 / flag 分布 / 样例
la.py list <包> [--filter 通配] [--limit N] [--json 文件]
```

实测：

```
$ la.py info 0174.gpk
容器      0174.gpk
条目      5,780
有名字    423（7.3%）
flag 分布 12×5772, 0×8

$ la.py list 0174.gpk --filter "*touxiangkuang*" --limit 5
4506  ui/nielian_icon_v4/kongjian_icon/icon_touxiangkuang_14.ktx  25700
```
