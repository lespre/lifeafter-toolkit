> 结论最早于 2026-10-21 得出，2026-10-27 整理进手册（`01_索引与产物/30_分析` 不入库，

## 一句话结论

**核心算术不在 Python/NeoX 字节码里，在 C++ 的 `HurtComp` 组件 `calc_internal` 里。**
Python 侧只有三类脚本：

```
1. 发起方     组装参数、提交伤害请求（如 WeaponControllerBase）
2. 回调钩子   监听 on_hurt_calc_finished / drone_after_hurt_calc，做 buff、特效、标记、追加伤害
3. 修饰层     装备 / buff / 特技 / 无人机 / 被动，在 C++ 计算前后插入增伤减伤
```

所以「找不到写着 `a-b` 的主伤害脚本」是正常的——它本来就不存在。

## 已验证：属性压缩（分段线性）

```python
def _apply_attr_factor(value, params, interval_key, factor_key, offset_key):
    if value >= 0 and offset_key in params:
        edges = params[interval_key]
        for i, edge in enumerate(edges):
            if value <= edge:
                break
        else:
            i = len(edges)
        value = params[factor_key][i] * value + params[offset_key][i]
    return value
```

- 调用点：`get_body_part_hurt_rate`（仅当攻击方是玩家）、`calc_boss_level_depress_hurt_rate`
- 压缩表：经典服 `compressed_attr_data` 181 行；简单生存服 `_kj1` 18 行（共用同一对端点）

| 属性 | 端点 |
|---|---|
| 砍伐速度提升 | `[450, 2450] → [200, 2200]` |
| 对玩家造成伤害增加（140） | `[0, 0.5, 1] → [0, 0.5, 1]`（恒等） |
| 受到玩家伤害减免（141） | 同上（恒等） |
| 简单生存服共用曲线 | `[0, 5118.75, 5724.75] → [0, 1800, 3225]` |

## 对 PvP 的直接结论（2026-11-03 已按字节校正）

```
倍率 = 1 + a_class( clamp(1 + Σ加成 − Σ减免, min_hurt_additional_rate, max_hurt_additional_rate) − 1 )
```

- 加成与减免**不是两个独立乘区**：先相减成一个桶，再夹到场景窗口，最后过 a_class 曲线
- a_class 曲线只作用在 `倍率 - 1` 上；**只有正区 Δ 会被改写**（`_apply_rate_factor` 的符号门）
- 140 / 141 曲线恒等只说明属性本身不被压缩，不能推出「PvP 不被压缩」——夹取发生在合并之后
- 部位与暴击才是独立乘区
