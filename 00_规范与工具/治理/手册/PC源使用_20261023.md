# PC 源怎么用（索引 / 还原树 / 边界）

日期：2026-10-23

## 三步

```bash

python 00_规范与工具/工具/工具库/01_解码定位复原/解包与扫描/build_pc_index.py \
    --root E:/mrzh/res --root E:/mrzh/Documents/gres \

# 实测：60 包 / 2,363,986 行 / 247 MB / 约 2 分钟

# ② 建 PC 还原树（名字从 PE 索引按 fid join）
python 00_规范与工具/工具/工具库/01_解码定位复原/解包与扫描/build_pc_tree.py \
    --out 01_索引与产物/41_还原树/pc_20261020 --workers 2

# ③ 取图（PE 优先，PC 兜底）

```

## 边界（重要）

| 能力 | PC 源 | 说明 |
|---|---|---|
| 资源树 | ✅ | 贴图 `.bc7`、模型、场景都在 PC 包里 |
| 取图 | ✅ | `pc_fetch` 走 `.bc7` → DDS/BC7 解码 |
| **配置表（cdata）** | ❌ | PC 包里只有资源，没有 `com/cdata` 脚本表 |
| **Wiki 板块** | ❌ | 所有 builder 都读 cdata，必须 PE / Documents 树 |

结论：**PC 能独立重建资源层，不能独立建 wiki**。wiki 的数据源永远是脚本表（PE / Documents 快照）。

## 与旧索引的差异

重建后的 pc_index 是**超集**：2,363,986 行 vs 旧 2,271,305 行（+92,681）。
旧库在早前生成时做过范围收敛；新库按包头如实全收，行数更多、不丢条目。
如需对比，旧库备份在 `pc_index.sqlite3.bak_20261023`。

## 常见问题：PC 能不能 2D 定位 / 能不能建 wiki？

### 2D 定位：**已经可以**

PC 包里图片是 `.bc7`（DDS 容器 + BC7_UNORM），定位链路与 PE 完全一样：

```
逻辑路径 → murmur3 fid → pc_index(pack,row) → 解块 → 转 PNG
```

```bash
python la.py find ui/xxx/icon_123.png      # 会同时列出 PE 与 PC 两个落点
python la.py img export ui/xxx/icon_123 -o out.png   # PE 未命中时自动走 PC
```

前提只有一个：先跑 `build_pc_index.py` 建出 `pc_index.sqlite3`。

### 建 wiki：**也能，但要换表根**

关键事实：PC 客户端**自带配置表**，在 `Documents/script.py314.lc.npk` 里
（解出来 `com/cdata` 下 2,318 张 `.py` 表）。所以 PC 不是"只有资源没有表"。

用法（已实测）：

```bash
# ① 先把 script.py314.lc.npk 解成目录树（工具：toolkit_core 的 npk 解块链）
#    产物形如 01_索引与产物/41_还原树/Documents/script.py314.lc.npk/com/cdata/*.py

# ② 指定表根，跑任意板块 builder
export LA_CDATA_ROOT=01_索引与产物/41_还原树/Documents/script.py314.lc.npk/com/cdata
python 02_wiki/web/tools/build_server_types.py     # 21 条
python 02_wiki/web/tools/build_gene_board.py       # 63 条
```

`_src.ROOTS` 默认顺序是 PE → Documents，`LA_CDATA_ROOT` 可以强制指定。
实测：用 Documents（PC）表根跑 `build_server_types.py`、`build_gene_board.py`，
条数与 PE 完全一致。

### 唯一真正受限的

- 部分板块的 builder 里写死了 PE 专属表名/字段（如 `*_auto_oversea_data_kj1`），
  这些在 PC 表根下可能缺表 —— 缺表时会报错，不会静默出错数据。
- 2D 图片来源：PC 是 `.bc7`，PE 是 `.ktx`，同一张图两侧尺寸一致，可互为校验。

## 双源实测（2026-10-23，用 PC 表根跑全部 builder）

表根：`Documents/script.py314.lc.npk/com/cdata`（2,318 张表）

| builder | PC 表根结果 | 与 PE 口径 |
|---|---|---|
| build_server_types.py | 21 | 一致 |
| build_gene_board.py | 63 | 一致 |
| build_kill_broadcast.py | 38 | 一致 |
| build_activity_master.py | 886 | 一致 |
| build_scene_balance.py | 63 | 一致 |
| build_misc_boards.py | desc 3,630 / text 14,841 | 一致 |
| build_talent_by_prof.py | talent 5,327 / gene 63 | 一致 |
| rebuild_edible.py | 4,557 | 一致 |
| build_text_boards.py | edible 3,986 / illustration 373 | 口径不同（现板 954 含更多层） |
| build_avatar_full.py | 454 | 现板 673，依赖 PE 取图 |
| build_upcoming_auto.py | 16（修复前直接报错） | 现板 50，PC 表更新、条目更少 |

**结论**

- **表驱动板块：双源可行**。9 个 builder 在 PC 表根下跑出与 PE 一致的条数。
- 原先写死 PE 路径的 `build_upcoming_auto.py` 已改为走 `_src`，现在两边都能跑。
- **资源/图片类板块**（头像、时装、皮肤）仍依赖 PE 取图管线；PC 侧取图能力有（`pc_fetch`），
  但 builder 还没接，要支持双源需要把这些 builder 的取图改成 `PE → PC` 兜底。
