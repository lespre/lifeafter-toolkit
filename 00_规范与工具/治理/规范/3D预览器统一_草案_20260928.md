## 二、目标：一个内核 + 薄壳

```
         ┌──────────────────────────────────────────┐
         │  内核  assets/viewer/neox-core.js        │
         │  · 场景 / 相机 / 取景 / 光照 / 布局       │
         │  · GLB 加载 + 自检                        │
         │  · 材质模式（源材质链 / 仅几何）           │
         │  · 诊断钩子（统一 __diag*）               │
         └───────────────┬──────────────────────────┘
                         │  被谁用
      ┌──────────┬───────┼────────┬──────────┬───────────┐
      ▼          ▼       ▼        ▼          ▼           ▼
  skin3d    zhanshen  weapon_   skeleton   board.html   （将来）
            （专题）   models    _preview   里的嵌入视图
```

**分工铁律：**

```
内核负责：把「一组 GLB（可选带材质清单）」变成「画面上能看能转的 3D」
内核不管：页面外壳、数据从哪来、导航、专题业务逻辑、文案
```

**⇒ 判据：如果一个页面里出现了 `new WebGLRenderer` 或手算 `Box3` 取景，那就是它在重写内核。**

## 三、内核的边界（明确做什么 / 不做什么）

### 做

| 能力 | 说明 |
|---|---|
| 加载 | GLB（含多部件）；可选的 `neox_material.json` 伴随文件 |
| 取景 | 给定模型自动算距离；支持预设视角（front/side/back/45°） |
| 光照 | **两种模式**：`source`（源 IBL cube，走现有材质链）/ `declared`（自声明三灯，明确标注不是源级） |
| 布局 | `single` 单模型 · `grid` 多模型并排 · `multiview` 每格不同视角 |
| 材质 | `source` 走 neox 链；`plain` 只贴基色；**拿不到源材质必须 fail-closed 并显示明确标签**，不许静默降级 |
| 自检 | 加载完回报：顶点数 / 是否有材质 / 取景半径 / 是否全黑 |
| 诊断 | 统一 `__diag()` / `__diagLight()` / `__diagAlb()` / `__diagTone()` |

### 不做

```
✗ 不做页面外壳（标题栏、按钮、返回链）
✗ 不读数据源（那是各页自己的事）
✗ 不引入新的渲染范式（继续用 three.js，不换 WebGPU/babylon）
✗ 不做导出/截图（那个走 CDP）
```

## 四、接口草案（先定形状，实现时再调）

```js
// 内核唯一入口
const viewer = NeoxCore.create(hostElement, {
  layout: 'single' | 'grid' | 'multiview',
  cols: 6,                       // grid / multiview 用
  materialMode: 'source' | 'plain',
  background: 'transparent' | 'color' | 'image',
  autoRotate: false,
});

await viewer.load([{ glb: url, material: url|null, label: '女衣 · 正' }]);
viewer.setView('front'|'side'|'back'|{yaw,pitch,zoom});
viewer.dispose();
```

**关键：`load()` 返回自检报告，页面可以直接显示**

```js
{ ok: true, items: [
    { label:'女衣 · 正', vertices: 16338, faces: 21004, hasMaterial: true,
      fidelity: 'source', radius: 9.6 } ] }
```

## 五、必须写进内核的硬约束（都是踩过的坑）

> 这几条不写进内核，每个页面还会各自再踩一遍。

```
① 【布局】多模型并排必须【1 canvas + 1 renderer】，每格各自 Scene + Camera，靠 scissor 切。
    N canvas + N renderer 塞 CSS grid 会取景失稳（有的格子被模型糊满、有的纯背景）。
② 【异步】回调里【不要】用 cells[cells.length-1] 取当前格 —— GLTFLoader 完成顺序不保证，
    会把 bbox/取景半径赋给错的格子（症状：N 格里只有 1 格出模型）。
    必须闭包捕获本格。
③ 【朝向】源网格 Y 轴朝下 ⇒ 必须 rotation.x = Math.PI，
    且要在 Box3.setFromObject 【之前】设（否则取景半径按未翻转的盒子算）。
④ 【双面】强制 material.side = DoubleSide —— 源网格三角绕序不可靠，单面会让整片几何消失。
⑤ 【取景】半径在加载完就算好存进该格，渲染循环直接用；
    不要把 Box3 存起来等渲染时再算（模型已居中平移，后算的 box 与 lookAt 原点不自洽）。
⑥ 【禁】canvas.toDataURL()（preserveDrawingBuffer:false ⇒ 读空白缓冲 ⇒ 全黑假象）。
⑦ 【验证】无头截图必须用 CDP 真时钟（--virtual-time-budget 会把定时器瞬间触发，得到假全黑）。
⑧ 【判据】「一批截图字节数完全相同」= 页面根本没跑起来（通常是 vendor 的 addons 404
    导致模块图断）—— 判据口诀：连 GLB 请求都没有 ⇒ JS 死了；有请求但 404 ⇒ 路径错；
    200 但空白 ⇒ 才轮到取景问题。
```

## 六、迁移路径（分阶段，每阶段都不破坏现有页面）

```
阶段 0  只抽「加载 + 取景 + 光照」三件（不动材质链）
        → 先让 weapon_models.html 用上（它最简单：122 行）
        → 验收：与原页面截图逐像素一致（或差异可解释）

阶段 1  把 skin3d.html / zhanshen.html 接过来
        → 这两页现在没有材质链，接入后【可选】开 source 模式

阶段 2  把 weapon_skin_viewer.js 里重复的部分改为调内核
        ★ 风险最高的一步 —— 它已上线且被 board.html 消费
        ⇒ 建议【不动它】，只在它外面包一层适配器，让其他页面也能用它的材质链

阶段 3  assets/3d 三族统一目录约定（weapon_skin / zs_series / zs3d）
        → 内核只认一种：<根>/<id>/{model.glb, neox_material.json, src_tex/, src_cube/}
        → 老族写适配映射，不搬文件（搬文件会动 141 个目录的连接数）
```

**阶段 2 的取舍要点**：`weapon_skin_viewer.js` 是 6,998 行的已上线实现。
**「统一」的目标是别再写第五遍，不是把它推倒重写。** 优先包适配器。
