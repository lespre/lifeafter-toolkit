## 一、★★★ 最重要的发现：NeoX「散文件优先」机制

来源：`ZhangFengze/NeoXResearch`（66⭐，NeoX 逆向最权威）原文

```
neox::filesystem::NXFileLoader 由多种 FileLoaderCreator 构造，统一在
NXFileLoaderCreatorManager 注册：

    NXDiscreteFileLoaderCreator   ← 散文件
    NXNpkLoaderCreator            ← npk 包

「通过动态调试确认……应该是采用了常见文件管理方式，
  【优先读取散文件，方便更新与调试】，没找到散文件则去资源包读」
```

### 这条为什么重要

```
它解释了 E:\mrzh\Documents\res\ 下那堆 .idx + *.wpk 是什么：
    那就是【散文件层】—— 热更把新内容放这里，引擎优先读它

⇒ 所以「官方下发的文件」不需要去 CDN 下大包，
  客户端已经把【变化的部分】单独放在散文件层了！

实测散文件层规模（本轮）：
    ui.idx 720 B / 19 条 · effect.idx 684 B / 18 条 · building.idx 288 B / 7 条
    character.idx 216 B / 5 条 · weapon.idx 180 B / 4 条
    model_high_2024.idx 108 B / 2 条 · model.idx 72 B / 1 条 · scene_bw.idx 72 B / 1 条
    ────────────────────────────────────────
    8 个家族共 48 条内容哈希（去重后）
⇒ ★ 这 48 条就是「上次热更下发的文件」
```

### 已实测的散文件层结构

```
.idx（SKPW）：头部 0x20 + 每条 0x24(36 B)
    条目 = [16B 内容 MD5][?4][pkg 低 8 位][offset][payload_size][header_size]
    实测：16 字节字段与载荷 MD5 逐条一致（60/60）⇒ ★ 存的是【内容哈希，不是名字】
    pkg & 0xff → 对应 <idx名><pkg>.wpk 实体容器（1DPW 头 + AC/PC/XC 前缀加密 + DTSZ/ZSTD 包装）
```

**⇒ 散文件层没有名字，但有内容 MD5 ⇒ 可以拿它去撞本地 230 万产物的 MD5 来命名。**

## 二、NeoX NPK 格式（同文实测，供对照我们自己的解析）

```
[0:4]   magic 'NXPK'
[4:8]   文件数量（小端 int）
[20:24] 元信息表相对文件头的偏移
中间是裸数据
之后是元信息表，然后文件结束
元信息表每项 28 字节：
    [0:4]   文件 ID（文件路径的哈希）   ← 就是我们一直在算的那个 fid
    [4:8]   文件数据相对文件头偏移
    [8:12]  文件数据大小
    [12:16] 文件数据解压后大小
    [24:26] 压缩方式（0 未压缩 / 1 zlib / 2 lz4，一般 2）
    [26:27] 加密方式（0 未加密 / 1 rc4 / 2 simple，一般 0）
注意 lz4 采用 block 压缩方式
```

**★ 另一条关键**：FileLoader 读出文件后，若 `this+44` 处存了 `neox::game::NXEncodeHook` 实例地址，
**会再调它的成员函数解密** —— 「参考链接里的 npk 解包没有处理这一步解密，导致解出的文件无法识别」。
（我们的 flag=0 走 AES 那条路，很可能对应的就是这一层。）

## 四、由这些思路得出的一条更近的路

```
你原本的想法：下载 CDN 上两个版本的 *.layers.*.npk，二进制 diff
    障碍：包是 1 GB 级，下载与比对成本高

★★ 有了「散文件优先」这条情报，可以少走一步：
    ① 散文件层（Documents/res/*.idx + *.wpk）已在本地，且只有 48 条
       ⇒ 它就是「上次热更下发的那些文件」
    ② 拿这 48 条的【内容 MD5】去撞本地 230 万产物的 MD5
       ⇒ 撞上就能给它命名（内容寻址，不需要路径表）
    ③ 若撞不上 ⇒ 说明该文件不在本地产物里
       ★ 但按铁律，这仍不能直接下「本地没有」的结论，要么补下载、要么另找判据
```

**★ 这条路的价值**：把「热更定位」从「包级」推进到「文件级/内容级」，
而且**完全不依赖名字字典**（走内容寻址）。
