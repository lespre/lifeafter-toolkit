## 0. 三句话结论

1. **最大单点故障是「审计产物目录搬家」而不是「数据没做」**：`web/analysis/audit/` 只剩 14 个 weapon_skin 文件，而构建链真正要读的 6 个 + 被脚本点名的 12 个全都在 `01_索引与产物/30_分析/site_analysis/analysis/audit/`（该镜像下有 7375 个文件）。`rebuild_item_master_v03.py` 现在**裸跑必挂**，报 `FileNotFoundError: web\analysis\audit\p4a3_classify.json`。→ 13 个文件一恢复就通，已有沙盒实证。
2. **`data/boards/common_item_text_sources.json` 全仓库不存在，且当前不可重生**：唯一产出方 `rebuild_common_item_text_sources.py` 里 `COMPARISON_SOURCE_ID = "lifeafter-classic-current"` 写死，而 `data/live_sources.json` 没有这个 `source_id`（只有 `lifeafter-root-py314-full`），跑起来直接 `ValueError`。补一行 registry 别名即可，实测 **16.4 s / 38571 行 / 100,805,553 B**。
3. **解释器本身也是隐式输入**：系统 `python`(3.14) 缺 `cryptography`，凡是过 `live_npk_reader` 的 builder 全部 `ModuleNotFoundError`。统一用 `00_规范与工具/环境/venv/Scripts/python.exe`（3.12.10 + cryptography 50.0.1）。

## 1. 方法

- **AST 扫描 + 静态求值**：对每个脚本建 `名字 → 路径` 环境（含 `__file__`），求值 `ROOT / "analysis" / "audit"`、`Path(__file__).resolve().parents[1]`、`SRC = ROOT/"x"/"y.json"` 等写法，得到**期望路径**。
- **只算读、不算写**：识别 `read_text/read_bytes/open('r')/sqlite3.connect/json.load/read_csv/imread` 等读取汇点；同名文件的 `write_text/json.dump/--out/DEFAULT_OUTPUT` 行整体排除。这一步很关键——不做的话 171~194 个**输出**会被误报成缺失输入。
- **四档（+1 档防御）**：

| 档 | 含义 | 处置 |
|----|------|------|
| A | 期望路径存在 | 正常 |
| B | 期望路径缺失，仓库别处有同尾文件 | `ensure --apply` 恢复（复制/硬链） |
| P | 期望路径在 web 部署树之外，或 web 前缀重复 | **改脚本**，不补文件（补=为 bug 造影子目录） |
| C | 全仓库都没有 | 跑产出脚本；无产出方则读者迁移 |
| U | 路径由参数/f-string 拼出，静态推不出 | 人工确认（见 §7） |
| X | 同名但**快照 id 不同** | 禁止恢复（防止灌错快照）；本轮 0 条 |

**已知边界**：`U` 是中性档，不代表缺失。114 条 U 里绝大多数是 `BASE_ENTRY = "018005.bin"` 这类「裸文件名 + 目录常量在别处」的写法，实际文件在 `config_work/*/entries/` 下齐备（5 个快照都有）。

## 7. U 档 · 114 条静态不可解，怎么人工确认

构成：裸 entry 名（`018005.bin`/`023928.bin`/`016783.bin`…，约 60 条）、`FASHION_IDENTITY_CANDIDATES.jsonl` 这类只写文件名的（约 30 条）、其余是 f-string 或 `args.xxx` 拼出的。

确认方法（已按此核过 entry 类）：目录常量在同一脚本里是 `ENTRIES = Path(r"…/config_work/<snapshot>/entries")`，`BASE_ENTRY` 再用 `ENTRIES / BASE_ENTRY` 拼接。实测这些 `.bin` 在 `328b8446 / 508BB5BD / 780363b86008 / BA8A239A` **四个快照下都齐备**，因此裸名类**不构成阻塞**，只是扫描器没有把"目录常量 + 文件常量"的两段拼接接上。

要看单条明细：

```bash
py -3 tools/ensure_builder_inputs.py scan --json ../analysis/scan.json
# rows[].tier == "U" 的 expected 即裸名，readers 给出读者脚本
```

## 10. 工具：`ensure_builder_inputs.py`

```bash
VENV=00_规范与工具/环境/venv/Scripts/python.exe
$VENV tools/ensure_builder_inputs.py scan                     # 分档总览
$VENV tools/ensure_builder_inputs.py scan --json out.json     # 机器可读
$VENV tools/ensure_builder_inputs.py ensure                   # dry-run，只打印计划
$VENV tools/ensure_builder_inputs.py ensure --apply           # 恢复 B 档（复制）
$VENV tools/ensure_builder_inputs.py ensure --apply --link    # 硬链，省磁盘
$VENV tools/ensure_builder_inputs.py ensure --root <沙盒>/web --apply   # 沙盒演练（绝对路径自动重映射）
```

安全边界：
- 只**创建**缺失文件，`target.exists()` 则 skip，**永不覆盖**；
- 不 import 任何 builder，不执行产出脚本（C 档只打印建议命令）；
- X 档（同名不同快照）一律不碰；
- P 档不补文件，只打印真实位置。
