## 三、★★★ 本轮纠正的错误（这部分最重要）

### 错 1：把「扫 0 命中」判成「配置表加密了」

`.nxs` / `_chs.py` 文字表扫 UTF-8 中文 → 0 命中，我判成「加密」。
**真因是定位错**：我用 `path_fid` 去算 **npk 容器里**的文件 —— 而 **npk 的 fid ≠ murmur3(路径)**
（只有 gpk 才是）。定位全错，读到的是别的文件。
→ 改法：npk 里的文件**直接用名字字典自带的 key**。

### 错 2：被自己带偏，又改判成 UTF-16

看见字节里有 `00 44 00 78` 就判 UTF-16。**子代理用「常用字占比」把它钉死了：**

| 文件 | 编码 | 常用字占比 | `的` 次数 |
|---|---|---|---|
| `desc_info_data_chs.py` | utf-16-le | 0.9% | 0 |
| `desc_info_data_chs.py` | **utf-8** | **69.3%** | **13,022** |

真中文在 3500 常用字表里占比都 >90%；UTF-16 那样解出来的「汉字」是随机字节配对的巧合。
→ **编码一直是 UTF-8，我错了两轮。**

### 错 3：「新增」判据用路径字符串比，11,802 条全是假阳性

字典存**正斜杠**（`building/jijian/x.gim`），二进制里挖出来是**反斜杠**。
拿字符串比 `s not in known` ⇒ 11,802 条全判成新增，**实际一条都不是新的**。
→ 改法：判「是不是新增」**永远比 fid**，路径字符串只用于展示。

### 错 4：图集认领没做全局去重，331 个 fid 被重复认领

「窗口内找尺寸匹配的 DDS」只做了同一 atlas 内去重 ⇒ 同尺寸的多个 DDS 被多个 atlas 页撞上。
实测出现**同一 fid 对 3 个不同路径**。
→ 改法：全局 `claimed` 集合，一个 `(容器, 行号)` 只能被认领一次。
→ 认领数 4,275 → 4,094（去重后），其中按偏移分层：

```
硬   −1/+1     2,315   容器内 [atlas][本体][json] 紧邻，铁律级
较硬 +2..+5      889
存疑 >=6         890   另存待核，不进字典
              ─────
★ 写进字典（硬+较硬）: 3,204 条
```

### 错 5（更早）：三个脚本各自写「逐行 glob」找产物

23,322 行 × 每次 glob 一个 5 万文件的目录 ⇒ 卡到天荒地老。
**我在基准测试里早就测出这个瓶颈，却没回头改那三支脚本。**
→ 改法：统一到 `artifact_locator`。

## 四、方法论收获（可推广）

**任何「自己声明了别的资源名」的文件，都能反推出别的资源的真名。**

| 文件类型 | 声明了什么 | 能否反推 |
|---|---|---|
| `.atlas` | 图集本体 png 名 + 尺寸 + 每个 sprite 名/坐标 | ★ 本体名能（+3,204） |
| `.c159` / `.gim` | 引用的 `.gim` / `.mesh` 路径 | 能定位，但名字**字典里已有了**（斜杠方向差异造成的假象） |
| Spine `.json` | attachment 名（= atlas 区域名） | ✗ 是内部区域名，无独立资源 |
| `.mtg` | 贴图路径（带 `textures/` 前缀） | ？路径格式待研究 |

**做法**：读它声明的名字 → 拼候选路径 → `path_fid` → 容器验证存在 → 且 fid 不在字典 = 新增。

**边界（实测负面结论，禁重试）**：
- ✗ **sprite 名不能用来还原文件名** —— 183,910 个候选，容器命中 1 个（还是已有的），新增 0。
