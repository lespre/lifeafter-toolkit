# 明日之后拆包器：统一索引与拆包流程

## 1. 唯一推荐入口

```powershell
python run_all.py index build
python run_all.py index status
python run_all.py find "common\env_map\qiangpi.cube"
python run_all.py extract "common\env_map\qiangpi.cube" "output\qiangpi.dds" --container "res.npk" --row 14213
python run_all.py verify
```

默认索引位于 `E:\la拆包项目\03拆包产物\indexes\lifeafter_files.sqlite3`。它是可重建的派生产物；`E:\mrzh` 始终只读。

## 2. 数据流

```text
逻辑路径
  ↓ 原大小写 + 反斜杠 + latin1 + 双种子 Murmur3
64 位 fid
  ↓ SQLite 精确查询
0 / 1 / 多个物理候选
  ↓ 唯一命中，或显式指定 container + row
边界检查 → 读取压缩载荷 → 按 flag 解码 → SHA256
```

统一索引同时纳入：

- GPK：完整读取 32B 的 `8×u32` 行，直接使用 `u6/u7` 组成 fid；多块容器保存逐块 payload delta。
- FPK：流式导入 `fpk_fid_index.json`，不一次性加载 253 MB JSON。
- NPK：读取 48B 索引行中的原生 fid。

同一 fid 的所有物理副本都会保留。工具不会自行选“第一个”，避免把补丁包、基础包和重复资源混为一谈。

## 4. 安全与证据规则

1. 源包只读；所有导出写入项目产物目录。
2. 索引构建先写 `.building`，完整检查后才替换正式库。
3. 多候选默认拒绝提取，必须用 `--container` / `--row` 明确选择。
4. 每次提取记录容器、原始行号、偏移、压缩/解压尺寸、flag 和 SHA256。
5. `index status` 显示 `stale=true` 时，先重建索引再做任何定位结论。
6. 路径变体默认关闭；只有显式 `--variants` 才尝试扩展名/大小写变体。
7. 文件命中只证明“路径→条目”，不自动证明纹理槽位或 shader 语义。
