## 四、数据地基规范（Phase 0，先做）

### 4.1 每条数据必带 provenance（对齐 06 日志三档证据标签）

```text
服务器分支：Documents 体验服 / 根包 / 正式服对照
包 SHA-256：源包哈希（包变更后旧记录自动降级待复证）
entry / row / key：表内定位
证据等级：结构已解析 / 业务链已核验 / 候选待验证
生成日期：YYYY-MM-DD
```

### 4.2 生成流水线（数据与页面分离）

```text
拆包工具库导出 JSON（带 provenance）
→ builder 脚本编译为静态站点（沿用豆包渲染思路）
→ 输出 皮肤库web 结构
```

### 4.3 版本管理

- 每次重生成前对比 diff，禁止无痕覆盖

## 七、风险与边界

- **版权**：游戏素材公网发布前确认展示范围；拆包物理路径/特效数据属灰色地带，建议公网只展示游戏内可见信息
- **判据分级**："未上线/独有"类结论必须标证据等级，候选≠确认
- **预算**：全程零 API 成本（纯静态、本地脚本），符合预算敏感约束
- **数据污染**：provenance 缺失的旧数据文件不得直接进 Wiki，先补源再入库
