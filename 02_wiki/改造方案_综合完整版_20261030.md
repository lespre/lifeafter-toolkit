# LifeAfter Wiki 综合改造方案（完整版）

- 日期：2026-10-30
- 范围：02_wiki 全站（数据管线 + 前端 + agent 作业流程）
- 背景约束：① 每两周热更后重新拆包、重建数据；② 拆包与补数据均由 agent 完成，且每次可能是无上下文的新 agent；③ 159 个数据板块共用 board.html 渲染壳。

---

## 0. 一句话总纲

**把"每两周由新 agent 重建一次数据"从靠记忆的体力活，变成一条幂等、可校验、可回滚的流水线；前端改造挂在这条管线上并行推进，不另开数据旁路。**

优先级铁律：管线 > 前端。前端美化不能解决口径漂移和静默缺数，管线不稳，前端做得再好也是沙上建塔。

---

## 1. 设计原则

1. **产物零手改**：`data/boards/*.js` 等产物只允许构建器生成，任何事后修补脚本必须并入主构建或退役。
2. **规则单一事实来源**：所有人工判定口径（服名、排除范围、字段来源、解析硬结论）只存在于 `rules/` 配置，构建器、RUNBOOK、memory 都引用它，不各自复制。
3. **agent 零记忆可作业**：新 agent 只读 RUNBOOK + rules/ + 现役脚本目录，即可完成全量重建，不需要任何聊天记录。
4. **缺失显式，禁止猜数**：数据源缺口生成说明性空卡，闸门拦截无溯源数据。
5. **一切变更可 diff、可回滚**：快照保留最近 3 版，产物灰度发布，出问题一键回退。
6. **前端功能的数据一律来自构建产物**（搜索索引、新增角标、更新日志），不开旁路脚本。

## 2. 目标目录结构

```
02_wiki/
  RUNBOOK_热更重建.md          # agent 唯一作业入口（本方案第 5 节为其骨架）
  rules/                      # 规则层：git 管理，永不自动覆盖
    equip_scope.yml           # 装备收录口径（排除键段/ID/名字正则、trial 合并）
    servers.yml               # 服名官方口径：kj1=简单生存服、base=经典服
    vehicle.yml               # 载具字段来源优先级、modding 指针基址=28、速度量纲说明
    boards/<board>.yml        # 每板声明式配置：数据源、过滤、字段中文名、排序、图标来源
  web/
    tools/
      build/                  # 现役构建器（只有这里被 RUNBOOK 引用）
      checks/                 # 现役闸门校验
      _archive/               # 退役探针与一次性补丁（全部移入，禁止执行）
    data/
      boards/                 # 产物层：纯生成，可随时删了重建
      search_index.js         # 产物：全局搜索倒排索引（构建期生成）
      diffs/                  # 产物：条目级 diff 报告
  snapshots/                  # 最近 3 版完整产物快照 + current 指针
```

数据三层隔离：**原始层**（01_索引与产物 冻结产物，每两周替换）→ **规则层**（rules/，人工/agent 维护）→ **产物层**（纯生成）。

## 3. 数据管线改造（核心）

### 3.1 幂等主构建

- 入口：`python web/tools/build/build_wiki.py --snapshot <YYYYMMDD>`
- 读原始层 + 规则层，全量重生成产物；同一输入重复运行结果逐字节一致。
- **构建缓存**：按"数据源 hash + 规则 hash"跳过未受影响的板，加速日常迭代；`--full` 强制全量。
- 构建结束输出 `build_report.json`：各板条目数、耗时、警告、闸门结果。

### 3.2 条目级 diff

- 与上一快照对比：新增 / 删除 / 字段变更，输出到 `data/diffs/<日期>.json`。
- **区分两类变更**：数据变更（源包变了）与口径变更（rules/ 变了），报告分开展示，避免"改了规则"被误读为"游戏改了数值"。
- 自动生成更新日志草稿写入 updates 数据源，人工/agent 只需润色。

### 3.3 质量闸门（红灯即停，不许带病发布）

| 类别 | 校验 |
|---|---|
| 波动 | 各板条目数环比波动 >20% 报警（防 inc 分片缺口类静默事故） |
| 溯源 | 每条数据必须带 source_path + row_key，且源真实存在 |
| 不变量 | 概率池总和=1；hp 曲线完整 150 级；navi_speed≤250；分服子卡不混排 |
| 资源 | 图标/海报文件存在性校验，缺失出清单 |
| 前端 | 构建后自动抽查 3 个板页面可渲染、无 JS 报错（smoke test） |

### 3.4 灰度发布与回滚

- 构建先出到 `snapshots/<日期>/`，审完 diff 再切 `current` 指针发布；线上始终可用。
- 保留最近 3 版，回滚 = 指针回切。

## 4. 前端改造（A 提前并行、B 挂进管线、C 暂缓）

### A. 轻量重构（与管线改造并行，互不相依赖）

- 拆 board.html（约 3000 行）为：`board.css` + `board.js` + 各板渲染器模块 + FIELD_CN 独立字典。
  - 新理由：agent 改 300KB 单文件上下文大、易误伤；拆分后改动小、diff 可审。
- 统一设计 token（色板/圆角/间距），消灭白底弹层与深色底冲突，4 套主题收敛为 1 套 + 暗/明切换。
- 移动端汉堡抽屉导航，复用 siteNav 数据（现 <900px 直接隐藏且无替代入口）。
- 老 URL 全兼容，交互不变。

### B. 体验升级（管线稳定后）

- **全局搜索**：构建期生成 `data/search_index.js`（名称/ID/别名 → 板+条目），门户搜索升级为跨板结果分组下拉。
- **条目详情页**：`board.html?b=xx&id=yy` 独立路由，左图右参数、技术字段默认折叠、底部"同系列/同池/相关条目"串联。
- **热更角标**：条目卡"本期新增/本期变更"标记 + 门户"本期热更"聚合区，数据直接吃 diff 产物。

### C. 长期形态（暂缓，2~3 个热更周期后评估）

- 组件化重写、图鉴/表格双视图、对比篮、收藏夹。
- 暂缓理由：双周节奏下更复杂的前端意味着更高的回归成本，等管线稳定再投。

## 5. agent 作业机制

### 5.1 RUNBOOK 骨架（每次开工唯一入口）

```
1. 拆包产物落到 01_索引与产物/xx_快照<日期>/（路径规范写死）
2. 跑 build_wiki.py --snapshot <日期>
3. 读 build_report.json：闸门全绿才继续，红灯查第 4 节对照表
4. 常见红灯对照：
   - all_equips 条目数暴跌 → 热更 inc 分片未入库（护臂案例）
   - 载具行 attrs 为空 → 193000~196999 段须走专用提取器
   - 名称缺失 → 查热更池 chs 字符串表
5. 审 diff 报告（区分数据变更/口径变更）→ 润色更新日志
6. 前端 smoke test 通过 → 切 current 发布
DoD（完成定义）：闸门全绿 + diff 已审 + 抽查 3 板 + 交接卡已写
```

### 5.2 交接卡

- 每次任务结束写 `state/handoff_<日期>.md`：本次做了什么、rules/ 改了哪些、遗留问题、下次注意事项。
- 新 agent 开工顺序：RUNBOOK → 最新交接卡 → rules/。memory 只留"规则在哪个文件"的指针。

### 5.3 tools/ 大扫除（第一步就做）

- 全部脚本三分类：`build/`（现役）、`checks/`（校验）、`_archive/`（退役，禁跑）。
- 每个一次性 add_*/apply_* 补丁判定归宿：已并入主构建 → 归档；长期规则 → 翻译成 rules/ 配置后归档。

## 6. 分期路线与验收

| 阶段 | 内容 | 验收标准（DoD） |
|---|---|---|
| 一期（1~2 天） | rules/ 首批规则 + RUNBOOK + tools/ 归档 + 前端 A 拆文件/主题/抽屉 | 新 agent 仅凭 RUNBOOK 能定位所有现役入口；前端老链接全通 |
| 二期（下个热更周期） | 幂等构建 + diff + 闸门 + 灰度发布 | 真实热更全流程一条命令跑通；人为制造一次数据源缺口，闸门必须报警 |
| 三期（管线稳后） | 全局搜索 + 详情页 + 热更角标 | 搜索跨板命中正确；角标与 diff 报告一致 |
| 远期 | 方案 C 评估 | 连续 2~3 个周期零人工干预后启动 |

**运营指标**（每周期记录）：重建总耗时、闸门拦截次数、人工干预次数、回滚次数。目标：人工干预逐周期下降直至趋零。

---

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 规则翻译时口径写错 | 首批规则只录入"已结案"结论；重建后与现产物 diff，差异必须为 0 |
| 一次性补丁遗漏导致数据回退 | 大扫除时先归档不删除；二期构建产物与现产物全量比对 |
| 闸门误报过多 agent 麻木 | 阈值先宽后紧，误报案例回填校验逻辑 |
| 前端拆分引入回归 | A 阶段不动数据与交互，仅搬移；老 URL 兼容 + smoke test |
| agent 绕过流程直接改产物 | 产物目录标注"生成物勿改"；发布前校验产物与构建输出一致性 |
