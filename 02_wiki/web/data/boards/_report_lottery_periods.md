## 3. 确定性 / 推断 / 未闭合

**行内直读（确定）**
- 纯外观抽奖：每池的 0x36 映射行给出 (槽位 → 0x86 明细行偏移)，槽位字节区间内的 0x27 组即该槽位道具 id。
  已用公开实例复核：池 391834 = 万圣绮夜，槽位 8/3/1 读出 魔女星愿(580215) / 第十三页(1110192) / 星紫迷踪-头饰(637330110)。
- 多时装抽奖：option 行同构；槽位 0x86 明细行的字段 14 = 子池/档位引用、字段 16 = 权重、字段 13 = 选项号或礼盒 id。
- 宸世臻藏：期次行 ui_rewards / new_rewards 的 jump 目标直接解出 id 列表（jump 偏移相对表体 blob）。

**推断（已在数据里显式标注）**
- 纯外观抽奖第 6 期（活动 3220 趴趴小宠）：`only_fashion_hd_lottery_conf` 的 key=6 行 schema 29 解码 overrun，
  期号→池号按「奖池表唯一未被引用的池 391407 + 池号随期号单调」反推。受影响条目的 `pool_binding` 字段标为
  `inferred-unique-leftover`，期次 notes 亦写明。其余 9 期的池号是行内直读。
- 期次名：活动 2793 / 2851 / 2865 / 2907 的 huodong_conf 行已被回收，名称显示为「（活动名未在活动表内）」，
  时间取 `only_fashion_hd_base_conf` 期次行的 slot_6 / slot_1。
- 多时装抽奖：同一配置号被多次活动复用（如配置 1/2/…），期次时间取最近一次活动实例，notes 里写明复用次数。

**未闭合（不臆造）**
- 宸世臻藏主池：`optional_conf_data.base_lottery_id = 390927` 只登记池号，成员表未闭合（本客户端
  `reward_pool_data` 是「奖励条目表」，池→条目索引未打通），故 member_count=0 并带 note。
- 宸世臻藏 ui_rewards / new_rewards 是【展示/兑换清单】，不是抽奖池开出内容；池的 kind 明确写「展示清单/兑换清单」。
- 纯外观抽奖池内的 UI 位（背景板/说明位，bg=39/2694、camera=0/1）没有道具组，不计成员；因此「槽位数 > 成员数」是正常的。
- 多时装抽奖子池引用的语义（字段 14）只在 A-SOUL（配置 10）与技能文档的 4/100/143 对得上，其余配置里该值更可能是档位号；
  因此 pool_id 用「配置-槽位」合成键，字段 14 单独存为 `sub_pool_ref`，不当作池号使用。
- 武器皮肤/典藏大奖类（super_fashion_lottery / lottery_big_reward）未纳入本板：它们的池成员需要 `reward_pool_no_item_no_list`
  的池→条目索引才能闭合，本次未打通，不写进看板。

## 4. 契约与校验

- `meta.evidence` 必须是 `build_wiki.py` 强校验的枚举字符串（structure/verified/candidate），
  写成对象会直接报错；分项计数改放 `meta.evidence_detail` 与 `meta.state_summary`。
- 每条 item 都有 id/name/evidence/evidence_level/status_tags/provenance；provenance 含 source_id、
  locator_chain（chain_status=replayed-structural、scope=record、no_cross_source_field_join=true、
  steps[decoded-table-row]）、source_lock_sha256（= 源包 sha）、upstream{package_sha256, table_sha256}、
  table、row_key、field_refs、name_source。
- `python tools/build_wiki.py`：退出码 0；`publication_contract_errors(board, strict_v2=True)` = 0 条。
  本板尚未登记进 `data/publication_policy.json`（按分工由主代理统一登记），登记后即走同一条 strict 校验路径。
