### 三个具体问题

| # | 问题 | 证据 |
|---|---|---|
| 1 | **① 线段太碎，且 ①-1 / ①-2 / ①-4 是同一件事** | 三条线的判据自己就说明了：`path_fid_*`（路径↔行）、`names_*`（名字↔行）、`bindict_entry` / `extract_usable`（行→内容）—— **都是「给一个东西，定到它在哪、是什么」**。它们产物类型相同（行级事实）、失败模式相同（定位不到）、消费者相同（下一次解析） |

| 3 | **段一多，标签就开始骗人** | ①-1 叫「定位复原」但它的判据里混着名字链；①-4 又叫「名字还原」—— 同一件事两个名字，看页面的人分不清该点哪个 |

```

   H-1 版本清单对比     release vs playertest → 新增/变更/删除包

```

## 三、带 H 的设计（为什么是「带」不是「线」）

### 判定依据：看它产出什么、给谁消费

```
① 线产出：行级事实        消费者：下一次解析
② 线产出：能看能听的图/音  消费者：人眼耳朵
③ 线产出：页面            消费者：浏览器
H 带产出：**「去哪里找」的导航**  消费者：三条线都要用
```

**三条线怎么用它（这是它算「带」而非「线」的理由）：**

| 线 | 怎么用 H |
|---|---|
| ① | 知道这次该去哪些容器/家族找（不用全库扫） |
| ② | 知道哪些资产是「新进包的」（进而判断能不能渲染、值不值得渲） |
| ③ | 知道哪些板块该标「新」或该更新快照 |

### 与现有两带的区别

```
带 D（数据契约）：是【接口】—— 三条线交换数据时的字段/口径约定
带 Q（质量治理）：是【闸门】—— 交付前必须过的检查
带 H（热更定位）：是【上游导航】—— 告诉三条线「新增的东西在哪」
```

**⇒ 它是**进入三条线之前的入口带**，所以画在三条线【上方/前面】，不是并列在下方。

### 段与判据

```
H-1 版本清单对比   @delta_entry（已有）· 服务端清单只读 · 键名漂移已动态识别
H-2 本地冻结与终态  变更容器发现 · sha 双验 · 写入窗口判定（游戏在跑时采到中间态）
H-3 包级归因        包名规律 <家族>.layers.<起>.<止>.npk · 家族词表 · 增量按家族聚合
```

**三段的边界**（防以后再糊在一起）：

| 段 | 输入 | 产出 | 明确不做 |
|---|---|---|---|
| H-1 | 服务端版本清单 | 包级增量（新增/变更/删除） | 不读本地客户端目录 |
| H-2 | 本地容器 mtime/尺寸 | 冻结副本 + 前后 sha + 终态记录 | 不对比内容 |
| H-3 | H-1 + H-2 | 「新内容归到哪一族」 | 不承诺「包里哪张图」——那要包内名字，哈希不可逆 |

## 四、① 线合并的设计

### 合并后 ①-1「定位与复原」装什么

```
方向一：路径 → 行
   @path_fid_single_source · @path_fid_cross_check · @find_chain_usable
方向二：行 → 路径（名字还原）
   @names_hash_selftest · @names_lookup_works · @names_dict_size · @names_index_queryable
   · @name_chain_single_source · @name_chain_hitrate · @name_tables_exist
方向三：行 → 内容（解析复原）
   @bindict_entry · @extract_usable · @parser_selfcheck · @generic_exporter
```

**⇒ 三条方向合起来就是一句话：给定「路径 / 编号 / 一条数据」，能定到它在哪、是什么。**

台账里用现有的 `【维度】` 标签（`【规模】【字段】【查法】【实测】`）组织，
**不需要新语法**。

### 为什么这三段能合、而 ①-0 / ①-2 不能合

```
①-0 索引地基   是【建地基】：产物是可重建的库，失败模式是「索引过期/不全」
               与 ①-1 的失败模式（定位不到）完全不同 ⇒ 分开
①-2 批量质检   是【放大】：单条能解 ≠ 能批量；产物是清单+报告，失败模式是「批量里的个别失败」
               且它有断点续跑/并发/限流这些横切关注点 ⇒ 分开
①-1 三段       产物同为「行级事实」，失败模式同为「定位不到」，消费者同为「下一次解析」
               ⇒ 合
```
