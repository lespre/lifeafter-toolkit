### 3.2 ★ 修掉 ②-4 的根因：一个过时的解析器副本

```
现象：render 对任何 mesh 都抛
      ValueError: buffer is smaller than requested size
      （render_neox_mesh.py:23 np.frombuffer(d,dtype='<u2',count=tv*3,offset=off)）

根因：render_neox_mesh.parse_mesh 是【本地复制的旧布局解析器】（按 v1/v2 硬偏移读），
      而 mesh 格式已演进到 ver4（变长流 + 附加流，meta 里有 layout_variant/n_extra）
      ⇒ 这正是「8 个 render 各带一份出图逻辑」的直接病灶

修：parse_mesh 委派给验证过的 la_glb.parse_part（→ mesh_parse2），
    返回形状不变 (P,uv,idx,meta)；定位用「向上找 00_共享核心」，不手算 parents[N]

影响面：7 个脚本共用它（extract_vcolor / make_material_id / render_material_layers /
        render_source_only / weapon_skin_pipeline / test_normal_ramp_direction）
        ⇒ 它们对 ver4 网格本来都是坏的，一并修好

验证：8 层图全出；带 --materials 时 Refraction/Subsurface 从 5,070 B → 60 KB（12 倍）
      ⇒ 证明 c159 里的晶体/次表面参数真的生效，不是出了张空白图
```

### 3.4 c159 的两套解析器：能力互补，暂不合并

```
c159_pair（老）    ：靠 "AnimParam" 标记找名字表；找不到就抛
c159_pair_v4（新） ：结构化输出 counts/method/confidence/reason，fail-closed

★ 实测（不是「新的就一定好」）：
```

### 3.6 ★ 修复解码器「莫名的 bug」：载荷长度不对被谎报成「格式不认识」

> 代码在 ① 线（`01_解码定位复原/解包与扫描/`），但病灶是在 ②线导图时踩到的。

```
★ 现象
   脚本 slice 到 900,000 B 后交给解码器，某条目报：
     UnresolvedCodec: flag=12 无法判定压缩类型: no codec matched {...}
   ⇒ 看着像「这个格式解码器不认识」，排查会被带偏去查格式/flag/字典

★ 真因（两层）
   ① classify_codec(packed, len(packed), decoded_size, flag)
                            ^^^^^^^^^^^^^^^^ 把「调用方实测长度」当成了「声明的 packed 大小」
      ⇒ 所有「长度相等」判据都在拿错数字算
   ② classify_codec 末段兜底 `if packed_size == decoded_size: return raw`
      ⇒ 长度巧合相等就原样直通，分不清「本来就是明文」与「调用方给的是已解码载荷」

   实测三条（声明 vs 磁盘 .dds）：
     r7783  packed 188,956 / decoded 566,612 / 文件 566,612  ← 文件是 decoded
     r7776  packed 270,105 / decoded 913,940 / 文件 913,940  ← 同上
     r7784  packed 151,859 / decoded 2,513,652 / 文件 2,513,652
   ⇒ bulk 写的是【解码后】载荷；再喂 unpack_entry 是二次解码，
     之所以「有时成功」全因 ② 那条兜底，而 slice 后长度不等 ⇒ 兜底失效 ⇒ 误报

★ 修法（都不破坏旧签名）
   · classify_codec 新增 declared_packed：给了先做长度体检，不符直接给准确诊断
   · npk_decode_entry 在 flag 分派【之前】先拦「给少了」（任何 flag 下都无歧义）
   · 新增异常 TruncatedPayload（别名 PayloadLengthMismatch，同属 RuntimeError）
   · 新增判据 CODEC_HOW_PAYLOAD_MISMATCH / CODEC_HOW_ALREADY_DECODED
   · npk_reader.unpack_entry 转发 entry / declared_packed（原先不传 ⇒ 体检不触发）

★ 验证（5 种情况，真实文件 + 合成数据）
   不传声明值（旧行为）  3/3 通过            ✓ 向后兼容
   真截断                TruncatedPayload: 载荷长度不符：给了 900000 B，声明 packed=270105，decoded=913940
   已解码载荷            how=already_decoded_payload，数据原样返回
   正规载荷（len==声明） 正常解出，不被误拦
   给多了                payload_length_mismatch + 准确报数

★ 契约测试
   新增 00_共享核心/测试/test_decode_payload_length.py（6 条）
   全量套件 84 → 90 passed
```
