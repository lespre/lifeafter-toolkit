## 〇、一句话结论

**【实测·解出来了】`ccaa5566` 不是一种"谜格式"，而是 NeoX 引擎的 `.pipe` 编译着色器变体缓存容器**——
它是「自定义 0x20 字节外层头 + 1~2 个**标准、未加密的 Microsoft DXBC** 着色器字节码 blob」。
DXBC 部分可用微软官方 `fxc.exe` **原样反汇编**（本报告就是这么干的，11/11 全部成功），
并能从 RDEF 反射块里读出**常量缓冲名 / 全部 uniform 变量名+偏移+大小 / 纹理与采样器槽名+寄存器号**。

⇒ **它不是贴图、不是压缩包、不是加密数据**；它就是这台游戏**全部已编译好的 VS/PS/CS 着色器**。
**它已被完全解开，无需解密也无需解压。**

### 2.6 DXBC 容器格式 —— **【实测】有权威公开规范，且与我们的实测完全吻合**

这是本次外部检索**最有价值**的部分（用于自证解析正确）。三个互相独立的权威来源一致：

**（a）微软自家仓库** `microsoft/D3D12TranslationLayer` `DxbcParser/include/BlobContainer.h` 原文：
```c
typedef struct DXBCHeader {
    UINT        DXBCHeaderFourCC;
    DXBCHash    Hash;
    DXBCVersion Version;
    UINT32      ContainerSizeInBytes; // Count from start of this header, including all blobs
    UINT32      BlobCount;
    // Structure is followed by UINT32[BlobCount] (the blob index, storing offsets from start of container
    //                                             in bytes to the start of each blob's header)
} DXBCHeader;

typedef struct DXBCBlobHeader {
    DXBCFourCC  BlobFourCC;
    UINT32      BlobSize;    // Byte count for BlobData
    // Structure is followed by BYTE[BlobSize] (the blob's data)
} DXBCBlobHeader;
```

**（b）LLVM 官方规范** `https://llvm.org/docs/DirectX/DXContainer.html` 原文：
> “The DXContainer header matches the pseudo-definition above. It begins with a four character code (magic number) with the value `DXBC`… Following the part header is an array of `PartCount` 32-bit unsigned integers specifying the offsets of each part header.”
> “Each part begins with a part header. A part header includes the 4-character part name, and a 32-bit unsigned integer specifying the size of the part data.”

**（c）vkd3d 实际解析代码** `libs/vkd3d-shader/dxbc.c` 原文：
```c
    tag = read_u32(&ptr);
    if (tag != TAG_DXBC) { ...  "Invalid DXBC magic." }
    checksum[0..3] = read_u32(&ptr) ×4;
    version = read_u32(&ptr);
    if (version != 0x00000001) { ... "DXBC version %#x is not supported." }
    total_size = read_u32(&ptr);
    chunk_count = read_u32(&ptr);
    for (i = 0; i < chunk_count; ++i) {
        chunk_offset = read_u32(&ptr);
        chunk_ptr = data + chunk_offset;
        chunk_tag = read_u32(&chunk_ptr);
        chunk_size = read_u32(&chunk_ptr);
        section->data.code = chunk_ptr; section->data.size = chunk_size;
    }
```

## ④ 结论：解出来了（以及已排除什么）

### 4.1 解出来了 —— 一句话定义

> **`ccaa5566` = NeoX 引擎的 `.pipe` 编译着色器变体缓存容器。**
> 外层是 0x20 字节自定义头（`"ccaa5566" + u32 版本=2 + u32 blob数 + 零填充`），
> 之后每 blob 一条 `{u64 阶段标志(0=VS/1=PS/2=CS), u64 长度}`，紧跟一个**标准、未加密的 Microsoft DXBC** 着色器字节码。
> DXBC 内固定含 `RDEF / ISGN / OSGN / SHEX / STAT` 五个 chunk；
> `RDEF` 里有完整的常量缓冲定义（名字、变量名、偏移、大小）与绑定资源表（纹理/采样器/UAV 名字 + 寄存器号）。

### 4.2 它能给出什么（对项目的直接价值）

1. **每条着色器变体的完整 uniform 清单**（名字/类型/偏移/大小/是否 unused）
   ⇒ 历史报告里 §四「从 DXBC 到通道公式」的路线**现在有 122,459 个样本可用**，不再是单点样本。
2. **纹理槽名 ↔ 寄存器号绑定**（`s_diffuse`=s0 / `Tex0`=t0 / `NeoxUBOLocal`=cb0…）
   ⇒ 可直接回答「光滑度到底来自哪张贴图哪个通道」这类挂起问题：从 RDEF 拿到槽名，从 SHEX 指令流拿到采样与通道（`.x/.y/.z/.w`）实际用法。
3. **材质/功能指纹**：槽名组合（`s_diffuse+s_normalmap+s_parammap` 三槽基础集、`t_vlm_*` 体素光场、`t_cloud_shadow_noise`、`s_multi_scattering_sampler` 大气散射 compute…）可做跨资产聚类。
4. **文件名复原路径已打通**（§3.5）：内容哈希撞磁盘 `.pipe` → 得到 `<材质名>.nfx2/` + `<变体hash>_<源hash>_d11.pipe`。

### 4.3 已排除的（带判据）

| 已排除的假设 | 判据（实测） |
|---|---|
| 压缩（zlib/gzip/deflate/bz2/lzma/zstd/lz4） | 8 种算法 × 8 种起始偏移 = 全失败；熵中位 2.4~2.7 |
| 分组加密（AES/XXTEA 等） | 长度不对齐 16、无 IV 规律、载荷内明文串直接可读 |
| 贴图 / 图像容器 | 0 张 DDS；历史 FX 审计 `effect_cache.gpk` 99,801 行 **0 张图片** |
| 序列化配置 / 对象图 | 无 `c159` 式的字段名文本表；而是 DXBC chunk 结构 |
| 已公开记录过的格式 | §2 的 8 个签名库 + Sourcegraph + GitHub 仓库搜索 + 7 个 NeoX 工具仓库全量扫描 → 0 命中 |
| 与 `cvis`/`c159`/`octl` 同族同布局 | 四者头部布局各不相同 |
| **本项目历史上"头 = 魔数+版本+版本"的说法** | 实测第二个 u32 是 **blob 个数**，非版本号（§3.2） |

### 4.4 仍未确认的（诚实标注）

1. 外层头 `+0x0C..0x1F` 那 20 个零字节是保留字段还是曾用字段 —— 抽样 2000 个**全零**，无法判定语义。
2. `gres\0000.gpk` 里 ccaa5566 的**真实路径名**：这 24,869 行在磁盘上没有对应的 `.pipe` 目录树可直接对比，**待确认**它们落盘时对应的文件名规则（推测与 effect_cache 同为 `<hash>_<hash>_d11.pipe`）。
3. 抽样只覆盖全库 **1.6%（2000/122,459）**，**未做 12.2 万全量逐条解析**；但 2000/2000 零失败 + 两容器各自 1000/1000，反驳"存在异类"的力度已较强。
4. `brotli` / `snappy` 本机无库，**未实测**（仅凭魔数不匹配排除）。
5. 计算着色器只占 `effect_cache` 的约 **0.5%**（5/1000）；全库该支线的真实占比**未精确统计**。
