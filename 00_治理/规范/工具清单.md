## 二、run_all.py 实际接了几个（重要）

**235 个脚本里只有 9 个直挂统一入口**，其余约 220 个必须单独跑。

| 子命令 | 调起脚本 | 方式 |
|---|---|---|
| `index build/status`、`find`、`extract`、`verify` | `10_应用核心/toolkit_cli.py` → `toolkit_core/{unified_index,paths}.py` →（反射）`06_皮肤定位链/gpk_npk_index.py` | `from toolkit_cli import main` |
| `overview` | `01_核心解包器/npk_reader.py` + `02_FPK工具/fpk_toolkit.py` | importlib 动态加载 |
| `restore` | `06_文件名还原/filename_restore.py` | importlib |
| `bindict-check` | `05_BinDict解码器/bindict_attrs_decoder.py` + `bindict_kj1_transfer_decoder.py` | runpy |
| `bridge-audit` | `10_应用核心/physical_bridge_audit.py` | importlib + sys.modules |
| `thfb`（源码内有，帮助未列） | `09_THFB工具/thfb_toolkit.py` | importlib |
| （间接）拆包执行 | `01_核心解包器/lifeafter_unpacker_full.py` | `toolkit_core/job_runner.py` 反射 |

另有 4 个经 toolkit_core 间接用到：`bindict_*.py`、`fpk_frames.py`。
`11_武器皮肤表定位/build_weapon_skin_table.py` 独立跑但复用 `toolkit_core/weapon_skin_table.py`。

**★ 结论：写新脚本时，先想清楚是「挂入口」还是「独立跑」。** 挂入口的别写自己的路径解析。

## 五、写新脚本时的规矩

```
1. 路径一律从 toolkit_core.paths 取（PROJECT_ROOT / DEFAULT_OUTPUT_ROOT / INDEX_ROOT）
2. 产物写 03_执行/ 对应子目录，禁写 02_资料/
3. 要挂入口 → 在 toolkit_cli.py 里加子命令；不挂 → 放对分类目录并写清 README
4. 一次性/探索脚本先落 03_执行/90_临时/，跑通稳定了再升级
5. 失败要记账（进失败清单），禁静默跳过
```
