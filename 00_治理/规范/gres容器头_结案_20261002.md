# gres/res 容器头「未解」问题：结案报告（2026-10-02）

承接：`00_治理/文档/审阅_1110171_文档定论.md` S4 登记的未覆盖面 ——
「`Documents\gres` 下 **35 个容器头格式未解**（非 HPGF/FPGH）」

## 一、结论

★★★ **不存在"未解格式"。那批容器头 = AES-ECB 加密后的 HPGF。**
解密后结构与已知 HPGF 完全一致（magic @4、第二标记 @56、行数字段同位）。**【实测】**

## 二、证据链

### 2.1 加密特征（先看到的现象）
```
res\ 大容器（weapon/scene_*/character_*/model_*/sound…）文件头：
  5a 44 f4 ae ec 52 64 dd ae ae 61 71 20 db 2a 50 | <8B 每文件不同>
  —— 前 16 字节【所有容器完全一致】，后 8 字节各不相同
熵高 · 前 4KB 内无 HPGF/FPGH/NXPK/SKPW ✗
⇒ 16B 固定前缀不可能是 IV（IV 必每文件不同）⇒ 是「固定明文头被同密钥加密」的产物
```
### 2.2 该 16 字节常量**不在**任何引擎二进制里（关键判据）
```
libclient.so (x86_64 80.4MB)  → 未命中 ✗
libclient.so (arm64  79.2MB)  → 未命中 ✗
lifeafter.exe  (39.8MB)       → 未命中 ✗
⇒ 它不是代码常量，是【数据】⇒ 支持"加密结果"而非"格式魔数"
```
### 2.3 复用项目已有密钥解密 → 明文可读 ✓
```
项目里已有 AES-ECB 解密工具链（本报告不复制密钥值）：
  01_工具/工具库/01_解码定位复原/资源索引/quick_scan_gres.py

用同一密钥对文件头做 AES-ECB 解密：
  weapon.gpk       明文偏移 4 = "HPGF" ✓  偏移 56 = "KPGF" ✓
  character_01.gpk 明文偏移 4 = "HPGF" ✓  偏移 56 = "KPGF" ✓
  model_01.gpk     明文偏移 4 = "HPGF" ✓  偏移 56 = "KPGF" ✓
```
