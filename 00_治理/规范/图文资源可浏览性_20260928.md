# 图文资源可浏览性 · 现状与要求

日期：2026-09-28 ｜ 状态：**要求已记录，转换未启动（等裁决）**
触发：用户口径「要确保一下拆包路径直接引用的图文资源格式，我在本地也可以浏览，这个注意一下」

---

## 一、要求

```
还原树是按【源路径】铺的 —— 那上面直接引用到的图文资源，
用户在本地要能【用浏览器/看图软件直接打开】，不需要额外的转换工具。
```

**为什么这条重要**：路径对了但打不开，等于「索引准了、东西用不了」。
这跟「解码产物要对标源路径格式」是同一件事的两面。

---

## 二、实测现状（2026-09-28）

### 判据

```
按扩展名应有的魔数  vs  文件实际魔数
  .jpg → FF D8 FF · .png → 89 50 4E 47 · .gif → GIF8 · .webp → RIFF+WEBP
  .tga → 无固定魔数 ⇒ 改用真判据：byte[2] image_type ∈ {0,1,2,3,9,10,11}
                       且 byte[16] pixel_depth ∈ {8,15,16,24,32}
  .dds → "DDS "
```

### 结果（还原树里有名字的目录，抽检 1,005）

| 扩展名 | 总数 | 抽检 | 魔数不符 | 浏览器可直接打开 |
|---|---|---|---|---|
| `.tga` | **63,526** | 400（另用真判据复检 600） | **0** | ✗ 否（浏览器不支持 TGA） |
| `.jpg` | 924 | 400 | 0 | ✓ 是 |
| `.png` | 173 | 173 | 0 | ✓ 是 |
| `.dds` | 32 | 32 | 0 | ✗ 否 |

**★ 两条结论**

```
✅ 扩展名全体诚实 —— 没有「说 .jpg 实际装 DDS」这类坑。两个判据都验过。
   （★ 自我纠正：第一版对 .tga 直接放行 = 没检；用 image_type/depth 复检后 600/600 合法。）
✅ 能直接浏览的：1,097 个（jpg/png），且都带源路径
❌ 打不开的：63,558 个（tga 63,526 + dds 32）
```

**⇒ 现状一句话：路径对了、格式诚实、但 6.3 万个浏览器打不开。**

---

## 三、方案（待裁决）

**不污染还原树** —— 它是硬链接 + 按源路径铺，改动会牵动 231 万条链接。

```
03_执行/41_还原树/          ← 原样不动
03_执行/42_可浏览层/        ← 新增，平行的第二棵树
   · 按【同样的源路径】铺，只放转好的 .png
   · 硬链接回原地不行（格式不同），只能是真副本 ⇒ 占空间
   · 附一份清单：哪些转了 / 哪些失败 / 各自原格式与尺寸
```

**转换器（现成的）**
```
DDS  → 走 dds_rgba_canonical（tex 命令用的就是它，R↔B 唯一修正点）
TGA  → PIL 直接读（Image.open 认 TGA）
两类都 → PNG（RGBA 保住透明通道）
```

**量级估算**
```
文件数  63,558
耗时    估 10~30 分钟（取决于单张解码 + 落盘）
空间    PNG 通常比源大 ⇒ 估 2~6 GB（待实测）
```
