# 容器与定位（路径表）

生效：2026-09-26 ｜ 实测来源：本文件所有结论都在 2026-09-26 现场跑过，带「实测」的为真输出

**这份文档回答：一条逻辑路径，怎么变成「哪个容器 + 行号 + 偏移」。**

## 〇、三条必须记住的边界

```
1. 路径哈希只在【资源容器】成立
   res.npk / res*.gpk / Documents\gres\*.gpk   ✓ 由路径算出 fid
   Documents/script*.npk 等【脚本包】          ✗ 不成立（5184 组变体穷举全不命中）
   *.fpk                                        ✗ 包内条目无路径
   ⇒ 脚本表只能走「登记表」，查表时必须先判断走哪条路

2. 索引库里【不存路径】
   lifeafter_files.sqlite3 的 entries 表只有 fid_hex，没有 path 列
   ⇒ 路径是「算出来的」（资源）或「查登记表来的」（脚本）

3. FID 是跨快照唯一对齐键，entry_index 不是
   实测同一 FID 在三个快照里是三个不同 entry：19394 / 18005 / 23049
   ⇒ 任何 entry_index 必须与 snapshot_id 一起用
```

## 一、三层结构

```
权威层  03_执行/10_索引/indexes/lifeafter_files.sqlite3    816 万行，fid 为主键
          └ containers / entries / meta

登记层  04_站点/web/data/table_index_entries_<snap8>.jsonl
          └ table_name → entry → file_id（脚本表的唯一入口）

站点层  04_站点/web/data/
          ├ id_locator_index.db      601 万行，identifier_type = fid | c1c2 | hash16
          ├ file_index_entries.jsonl 同源，带 client_channel
          └ asset_path_dictionary.jsonl  34,679 条资源路径 → entry 序号
```

**索引库 schema（实测 PRAGMA）**
```sql
CREATE TABLE containers(container TEXT PRIMARY KEY, kind TEXT, bytes INTEGER,
    mtime_ns INTEGER, rows INTEGER, status TEXT, error TEXT);
CREATE TABLE entries(fid_hex TEXT NOT NULL, container TEXT NOT NULL, kind TEXT NOT NULL,
    row_index INTEGER NOT NULL, offset INTEGER NOT NULL, payload_offset INTEGER NOT NULL,
    packed INTEGER NOT NULL, decoded INTEGER NOT NULL, flag INTEGER NOT NULL, source TEXT NOT NULL,
    UNIQUE(kind,container,row_index));
CREATE TABLE meta(key TEXT PRIMARY KEY, value TEXT NOT NULL);
```
`source` 三个取值（实测 group by）：`gpk-table-8u32` 4,579,792 / `fpk_fid_index` 2,012,297 / `npk-table-48b` 1,568,686

## 二、查法（三条路线，先判断走哪条）

### 路线 1：资源容器（最常用）

```
逻辑路径 → path_fid() → 64 位 fid → sqlite 查 container/row/offset
```

```bash

    --container "res.npk" --row 14213
```

**路径→fid 的算法**（`toolkit_core/unified_index.py:88-124`）：
```python
# 路径先做 "/" → "\"，再用 latin1 编码，保持原大小写
# 高 32 位 seed = 0x77777777，低 32 位 seed = 0x66666666
fid = (murmur3(path, 0x77777777) << 32) | murmur3(path, 0x66666666)
```

### 路线 2：脚本表（**不能走路径哈希**）

```python
import json, sqlite3, os
SNAP = '328b8446'
WEB  = r'E:\la拆包项目\04_站点\web'
DB   = r'E:\la拆包项目\03_执行\10_索引\indexes\lifeafter_files.sqlite3'
TARGET = r'com\cdata\common_item_data_base.py'

# 步骤 1：路径 → entry → file_id（走 table_index_entries）
for line in open(os.path.join(WEB, 'data', 'table_index_entries_%s.jsonl' % SNAP), encoding='utf-8'):
    d = json.loads(line)
    if d['table_name'] == TARGET:
        print('entry=%s file_id=%s' % (d['entry'], d['file_id']))
        # 实测: entry=19394 file_id=B42760CCA41DBC25 role=base size=1990255
        fid = d['file_id']; break

# 步骤 2：file_id → 物理容器/行/偏移（FID 才是跨快照对齐键）
con = sqlite3.connect('file:' + DB + '?mode=ro', uri=True)
for r in con.execute('select container,kind,row_index,offset,payload_offset,packed,decoded,flag '
                     'from entries where fid_hex=?', (fid,)):
    print(r)
    # 实测: ('Documents\\script.py314.lc.npk','npk',19460,149214708,149214708,905648,905648,0)
```

**交叉核对入口（三者应一致，不一致就是换包了）**
```
① registry/sources.json#table_sources                    logical_path + snapshot_id + FID + entry
② registry/tables.json#snapshot_payload_bindings         entry_index + file_id + declared_size + status
③ registry/payload_maps/<snapshot_id>.json#fid_to_entry   fid → entry
   ⚠ payload_map 不是全量路径表：path_to_entry 只在 328b8446 里有，且仅 21,257 条，主表不在其中
```

## 三、各容器的边界与坑（查之前必读）

| 容器 | 路径可哈希？ | 取 fid 方式 | 偏移注意 |
|---|---|---|---|
| `res.npk` / 资源 npk | ✅ 成立（实测） | 48B 行首字段 = 路径双 murmur3 | `offset == payload_offset` |
| `res*.gpk` / `Documents\gres\*.gpk` | ✅ 成立（实测） | 读 32B 行 `8×u32`，用 u6/u7 组成 fid | **必须按行所属块加 payload delta**（实测差 36B） |
| `Documents/script*.npk` | ❌ **实测否** | 只能走 entry/FID 登记表 | entry_index 与 row_index 是**两套编号** |
| `*.fpk` | ❌ 包内无路径 | 只能 fid 查 `10_索引/fpk_fid_index.json` 的 `fid2info` | frame_offset = zstd 帧起始 |
| `.idx`（wpk 旁侧） | 以 hash16 = 解压内容 MD5 为标识 | — | pkg 分卷号 255 = 旁侧散装 |

**flag 语义**：`0` = stored / `2` = LZ4 / `12` = zstd

## 四、registry 文件职责表

|---|---|
| `chains.json` | **领域状态机**，不是路径表。4 条链（item/fashion/weapon_skin/lottery）× 六维状态 |
