## 〇、拿到一个任务，怎么用这张表（30 秒版）

```
1. 先定【格式】行：这个任务读写的字节是什么容器？（GPK / FPK / NPK-资源 / NPK-脚本 / WPK-1DPW / THFB / nxs-BinDict / 网格与渲染 / 贴图 / 音频）
2. 再定【职能】列：我要它给我什么？索引 / 定位 / 解码 / 提取 / 转换 / 导出 / 验证 / 报告
3. 格子里的候选按 ★ → ● 顺序挑（★ 可 import，● 只能整跑）
4. 格子是 —（缺） = 这个能力现在没有，别浪费时间找；直接看第七节缺口
5. ✝ 是弃用候选：能跑不代表能信（多数指向已不存在的目录），别拿它当基线
```

**两条铁律（来自 `00_治理/规范/容器与定位.md` 与 `工具清单.md`）**

```
· 定位先走索引：逻辑路径 → run_all.py find/extract（unified_index + sqlite），不要写新的路径扫描脚本
· 路径哈希只在【资源容器】成立；script*.npk 与 *.fpk 不成立 ⇒ 这两行没有「路径→条目」的能力，只能查登记表
```

**图例 / 状态判定规矩**

```
★ 库   = 被至少一个其他脚本 import（实测 grep 到 import 者），或位于 toolkit_core/ 包内作为模块 → 可复用
● 入口 = 有 main/argv 或顶层直接执行，且没有 import 者 → 只能整跑
✝ 弃   = 一次性探索 / 含死路径 / 已被新脚本取代（第六节逐条给出理由与「若删会丢失什么」）

※ 「顶层脚本(无 main)」在清单里是第三种类型，本表按「能不能整跑」并入 ●（没有参数解析，得先改文件里的常量）。
※ 有些脚本两副身份（既是 import 目标又有 CLI），本表标 ★ 并在判据里注明。
```

6. **`*.idx` / `.thx` / `.nxs` 三种旁侧索引文件没有统一索引器**：现在各自为政。
7. **WPXK/THFB/GPK 三行 0 测试**：回归靠人眼。而 FPK 有 2 个、nxs 有 6 个、贴图有 2 个 → 测试覆盖严重不均。

9. **武器皮肤 `grade/level → 中文品级` 映射工具缺位**：`容器与定位.md` 明令「无映射证据，禁止派生」，但**没有脚本去取证**（只有 `weapon_skin_table.py` 出 listing_status=unresolved）。
10. **index 新鲜度闸门覆盖不到热更**：`run_all.py index status` 检不出「索引对着一份未登记的热更版本」（`容器与定位.md` 第六节），**没有脚本做容器 sha256/字节数 与登记册的自动比对**。
