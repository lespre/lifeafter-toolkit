## 五、建议：**不扩成四条线，改「三线 + 子线 + 两横切带」**

### 为什么不扩成四条/五条线

1. **数据不是第四条对等线，它是线的"交接面"**：①②③ 的边界是"动作"（解析 / 渲染 / 展示），数据层的边界是"契约"（这行算不算事实、口径是谁定的、拿不到怎么标）。把它平级成线，会立刻出现"①说解出来了、②说按数据渲染、③说按数据展示，**三者对不上时谁改口径**"——这正是 `MANIFEST.json`（锁 sha256）+ `RULES.json` + `residuals` 现在在干的事。
2. **缺口里有 5 条（3/7/8/9/11）压根不是"哪条线"，而是"没人负责的地基与闸门"**：索引维护、交付打包、验收自检、工具治理、证据/残留。**再加线也装不进它们**，只会让线数膨胀。
3. 已有先例：`toolkit_core/lines.py` 的"两条线"就是这么失败的——它把数据当"文字线"塞给渲染线的对立面，结果 `script*.npk`（脚本包）和 `NPC 表`（数据表）被归到同一柜子里。

### 建议落地形态

```
① 解码定位复原线
   ├─ ①-0 索引地基    建/校/新鲜度/容器登记（run_all index build|status|verify + FPK 索引重建）
   ├─ ①-1 定位复原    路径→fid→行→偏移；名字↔条目（NAME_LOCATOR/name_chain）；定位链 locator_chains
   └─ ①-2 解析复原    BinDict/attribute_data/THFB/脚本包 → 行级事实；WPK·1DPW；FSB5 载荷

② 图文音频渲染线
   ├─ ②-1 3D（装配帧→网格→GLB）   ②-2 贴图（DDS/立方体/立绘海报）
   ├─ ②-3 音频（bank→WAV）        ②-4 出图与校色（非交付面 PNG / qc.json）

③ 前端展示交互线
   ├─ ③-1 页面与看板（wiki/board/workbench/专题页）
   ├─ ③-2 **服务与契约**（services / api.server / api.cli / wiki_server / 启动.bat）
   └─ ③-3 资产落地与投影（五件套落地器 / build_boards / manifest / publication_policy）

━━━━━━ 横切带 D：数据契约带（不是线，是①与③之间的唯一接口）━━━━━━
   domains/*（builder + rules + schema）· artifacts/{active,historical} · registry/（snapshots/sources/
   namespaces/chains/legacy_status）· evidence/ · residuals/ · services/store.py 读边界
   铁律：上游只写 artifacts/active；下游只读 artifacts/active；口径写在 RULES.json；unresolved 必须留

━━━━━━ 横切带 Q：质量·交付·治理带（不是线，是三条线都要过的闸门）━━━━━━
   验收自检（wiki_acceptance/selfcheck/3d_pixel_verify/tests 100/REGRESSION）· 发布门禁（publication_policy）
   · 索引新鲜度闸门 · 交付打包（02_资料/交付定版器，**现在缺**）· 工具治理（run_all CLI / paths / 死路径）
   · 站点与目录清理 · 治理规范与 git
```

**三条必须立刻补的实名登记**（否则改了线还是找不到人）：
1. 给 **`03_执行/30_分析/数据表/` 63 个孤儿产物**建 `MANIFEST`（谁生成 / 能否重建 / 正本在哪），或明确它只是"过程稿，正本在 `data/exports` 与 `artifacts/active`"。
2. 给 **索引 sidecar 三份 json**（`lifeafter_files_{build,status,verify}.json`）补生成脚本 —— 现在生成器已消失、路径还写着重构前位置。
3. 建 **`run_all.py pack <skin_id>`**（《待办》已列为计划）：一次出前端五件套 + 跑 rebuild 门禁 —— 这是 ①→D→②→③ 的**唯一缝合点**，也是「交付物打包」缺口的正解。

## 六、一句话结论

三条线**能覆盖约 2/3 的现场产物**（渲染线最干净、前端线差一个"服务层"、解码线需拆 3 个子线）；
剩下 **12 类无归属**里，真正的病根只有两个：**①数据契约没人管（口径/版本/不可重建）**、**②地基与闸门没人管（索引维护、验收自检、交付打包、工具治理）**——这两件事再加十条线也装不下，必须显式立成三线之外的**两条横切带**。
