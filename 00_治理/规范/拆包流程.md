## 对标出处（每条铁律从哪来的）

本项目的方法不是自创，是对标 23 个主流拆包器/数据项目后收敛的。出处如下：

| 本项目的做法 | 对标来源 |
|---|---|
| 先索引再解包，禁整包解 | CUE4Parse `IoStore` 的 TOC-优先 + 惰性载荷；AssetStudioMod 的 `-m info` 零副作用侦察 |
| 身份与名字分离、路径是可选列 | IoStore 用 12 字节 `FIoChunkId` 作主键，`HasDirectoryIndex` 可为 false |
| 压缩方法索引化（0=stored，未知直接报错） | CUE4Parse `CompressionMethodIndex` + AssetStudioMod `--block-comp` 强制覆盖 |
| 多块偏移按行所属块算 | IoStore 的 `firstBlock=offset/blockSize` + `CompressionBlocks[]` 块表 |
| 解析失败「原样落盘 + 标记未解析」 | UnityPy `extractor.py` 里 MonoBehaviour 失败回退 `.bin` |
| 认不出也给确定性占位名，永不静默丢条目 | AssetRipper `path_<id>`、ZenHAX `__Unknown\FD77A2A5`、QuickBMS `%08x%08x` |
| 命中必须带置信度/碰撞检测 | Neversoft 的 QbKey（命中数须 ≥ 碰撞数 ×50 才存映射） |
| 失败清单是一等产出 | AssetRipper `/FailedFiles` + 每条打 `Assets/Path/Type/PathID` 四元组 |
| 根目录放「可删性声明表」 | reb3 的 `.gitignore` 逐目录注释重建脚本；Unity 对 `Library/` 的定义 |
| 产物默认拒绝覆盖，覆盖是显式开关 | AssetStudioMod `-r/--overwrite-existing`；QuickBMS `-o/-k/-K` 三选一 |
| 阶段用目录固化、库/CLI/GUI 平级 | AssetRipper `Source/` 按阶段分；AssetStudio 顶层「核心库 / CLI / GUI」 |
| web 层是挂旁边的壳，不 import 核心 | AssetRipper `GUI.Free/Program.cs` 全文 3 行；反例 `stable-diffusion-webui` |
| 健康测试：删掉 web 主干还能跑 | GhidraMCP / ReVa 的 agent 只走 HTTP，不 import 核心 |

**★ 本项目强于通用工具的两点（要保住）**
```
1. 名字哈希正查   路径 → 双 murmur3 → 64 位 fid → 条目
                 通用工具只能靠已知名字表，我们能由路径反查
2. bbox 认领      编译网格不带名字时，用装配帧声明的 BoundingInfo 与实测 bbox 比对
                 实测精度 rel 0.0005~0.003
⚠ 两者都有前提：见 `容器与定位.md` 的「三条必须记住的边界」
```

**⊘ 已明确不做的（避免过度工程）**
```
✗ 自建 BMS 式通用脚本引擎（单语言产线，收益 0）
✗ Kaitai/DFDL 跨语言编译链
✗ 继续投预算给名字哈希字典穷举（已强否定）
✗ 照抄 AssetRipper/UABEA/FModel 的 CLI 参数（它们官方根本没 CLI）
✗ 把 816 万行索引进向量库（agent 用「先查表、后检索」，见前端交付要求）
```

### ① 建索引

| 项 | 内容 |
|---|---|
| **目标** | 把容器（GPK/FPK/NPK）的条目全量登记进 SQLite，得到「逻辑路径 → 容器/行/偏移」的映射 |
| **命令** | `cd 01_工具 && python run_all.py index build` |
| **输出** | `03_执行/10_索引/indexes/lifeafter_files.sqlite3`（约 1.5 GB / 816 万行） |
| **耗时** | 约 15 分钟 |
| **验证点** | `python run_all.py index status` 必须满足：<br>· `quick_check: "ok"`<br>· `failed_containers: 0`<br>· `inventory_stale: false` |
| **失败处理** | `failed_containers > 0` ⇒ 记下容器名，**不要重跑全套**，只针对该容器排查（见 `异常处理.md` E2/E6） |

> **何时必须重建**：源包热更后（`inventory_stale: true`）、容器文件增删后。

### ② 定位条目

| 项 | 内容 |
|---|---|
| **目标** | 由「逻辑路径」找到「容器 + 行号 + 偏移」，且**唯一命中** |
| **命令** | `python run_all.py find "character/players/m002011/m002011.gis"` |
| **输出** | 候选列表（含 `fid_hex` / `container` / `kind` / `row` / `offset` / `flag`） |
| **验证点** | · `status` 必须是 `OK`（唯一）或 `AMBIGUOUS`（多候选，**必须显式指定**）<br>· 命中后**必须校验魔数**（防 `--find` 假阳性，见下） |
| **失败处理** | 0 命中 ⇒ **先自证伪**：换斜杠方向重试、关 `variants` 重试、确认路径拼写。<br>**禁**由「没找到」反推「资源不存在」 |

**★ 本项目的两种认领法（比通用工具强，要保住）：**

```
A. 名字哈希正查（首选）
   路径 → murmur3 双 seed → 64 位 fid → 索引行
   注意：先 "/" → "\"；A=murmur3(path,0x66666666)、B=murmur3(path,0x77777777)
        m_Hash = B("X8") + A("X8")

B. bbox 认领（编译网格不带名字时的兜底）
   装配帧声明的 BoundingInfo half-extent  vs  实测网格 bbox
   实测精度 rel 0.0005~0.003
   ⚠ 必须关掉候选名变体（variants=False）+ 校验魔数，否则撞哈希假阳性
```

**★ 已证伪、不许再试的认领法：**
```
✗ bbox 尺寸匹配（v3~v12 共 10 版全败）
✗ 顺序配对（装配帧 ↔ 网格组，数量对不上）
✗ IoU 判据（正控 0.6499 vs 负控 0.6365，无区分力）
✗ 空间相关性（武器正控 0.1677 有效，时装失效）
```

## 环境契约（2026-09-26 确立）

### 唯一解释器

```
E:\la拆包项目\.venv\Scripts\python.exe
```

**所有拆包 / 索引 / 解码 / 渲染命令都必须用它。** 依赖锁版本见 `01_工具/requirements.lock.txt`（38 包）。

### 为什么单独立环境

```
此前项目【借用】两个外部环境，谁都没写明该用哪个：
  py312_env（在项目外）   ✓ 依赖全齐，但它被清掉项目就废
  hermes venv（Hermes 的）✗ 缺 zstandard / lz4 / texture2ddecoder / capstone

后果不是「报缺依赖」，而是【散架式失败】：
  · 同一个命令换个解释器就报别种错（ModuleNotFoundError 混在业务逻辑里）
  · 分不清是「工具坏了」还是「环境不对」
```

### run_all.py 启动自检（已内建）

每次运行都会检查解释器 + 8 个关键依赖，**只警告不阻断**：

```
■ 在项目 .venv 里        → 静默通过
■ 在别的环境里           → 打印当前解释器 + 推荐路径
■ 缺关键依赖             → 逐个点名 + 说明影响哪个命令 + 给安装命令
```

判据：**缺依赖属于「当前环境不支持（UnsupportedFeature）」，不是「不该发生（Internal）」**
⇒ 点清楚缺什么、影响什么，而不是丢一个 ModuleNotFoundError 让人猜。
（这条来自对标：paksmith 把这两类错误分成两个变体。）
