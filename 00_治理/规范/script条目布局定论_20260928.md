## 一、条目布局（实测自洽）

```
条目 = [4B 小端名长 L][L 字节模块名] + N × [4B 小端块长][块数据]
```

**自洽性验证**（这是结构正确的硬判据）：

```

  沿 [4B长度][数据] 走出 21 块，正好消耗 18454 / 18454 字节  ✓
```

## 二、数据是【明文】（不是加密）

```
块数据的熵       3.4 ~ 5.0（明文区间；密文会 >7）
可读串（真函数名）：
  'ignore_active' · 'schedule_open_levels' · 'is_training_rank_in_season'
  'ScheduleHelpers' · 'get_new_schedule_ui_data' · 'get_prof_level'
  'player' · 'prof_comp' · 'X9Esports'
```

## 三、踩过的两个弯路（记下来别再犯）

```
✗ 弯路 1：把 [名后第一个 4B] 当成「数据长度」
   实际那只是一块（224 B）的长度，条目里【有 21 块】。
   正解：它是 [4B 块长][块] 的重复结构，要循环走到末尾。

✗ 弯路 2：把 [0:4] 当所有条目的「名长」
   实测只有【大条目】是这个结构；另有小条目（22 B / 41 B）
   [0:4] 读出天文数字（3227701593 / 4030910882）⇒ 它们不是 [名长][名]
   正解：解析前先校验「名长合理 + 名字可打印」，否则换解析分支。
```
