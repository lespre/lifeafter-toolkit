## 一、先排除「是我们方法差」这个可能

**对照实验：path_fid 对各路径族是否有效？**（路径正算 fid == 行内 fid 才算通过）

| 路径族 | 样本 | 对上 | 对不上 |
|---|---|---|---|
| `ui/spine_new/...` | 400 | **400 (100%)** | 0 |
| `ui/shizhuang_icon/zengsong/...` | 32 | **32 (100%)** | 0 |
| `ui/shizhuang_icon/...` 全族 | 82 | **81 (98.8%†)** | 0 |
| `weapon/skin/...` | 200 | **200 (100%)** | 0 |

† 1 条**在索引里查不到行**（不是算错），其余 0 条算错。

**⇒ 结论：`path_fid`（双 seed murmur3 + 反斜杠）对这些路径族完全有效。**
**所以「按名撞不上」不是算法问题** —— 这条排除了，才能往下说。

## 四、问题三：atlas 明明有「目录」，却配不上页

`huanyeshenyu_female.atlas`（实测，`gres\0000.gpk` r8585）原文：

```
(空行)
huanyeshenyu_female.png        ← 页名
size: 2048,2048                ← ★ 页属性行【不带缩进】
format: RGBA8888
filter: Linear,Linear
repeat: none
hy_w105                        ← 从这行起才是切片（也无缩进）
  rotate: false
  xy: 1154, 803
  size: 224, 342
  orig: 257, 343
  offset: 22, 1
  index: -1
```

**★ 关键：atlas 里写着每个切片的【名字 + 精确坐标】—— 210 个切片，矩形并集覆盖 84.2% 的页面积。**

**⇒ 只要能把「atlas ↔ 页」配上，就能按坐标裁出【有名字的小图】**
**（这正是用户一开始要的「单头饰小图」的形态）**

**试过并失败的配对法：**

| 方法 | 结果 |
|---|---|
| 用声明页名算 fid | 0 命中 |
| 1,260 个写法变体 | 0 命中 |
| **alpha 内外差**（正确页：矩形内不透明、矩形外透明） | 最佳候选 gap 仅 **0.322**，且是 `model/login45` 的登录纹理 —— 不是 spine 页 |
| 按声明尺寸（2048×2048 RGBA8888 → ~16.7 MB）筛 | 全库仅 18 行，无一是它 |

**⇒ 倾向结论：`huanyeshenyu_female` 这个 spine 页**确实没打进本地包**（atlas/json 进了，页没进）。**
⚠ 但按项目铁律，这条**还需再用「位置/内容」判据证一次**才能定案，本轮只到「倾向」。

## 六、真正的结论与建议

```
★ 结论：这不是「字典不够大」，是【资源在分包体系里就不以完整路径存在】。

   · 44.86% 覆盖率里没名字的那 55%，按容器分：
     scene/scene_bw 类 ~70 万行（名字是程序拼的）
     ui_0*.gpk / model_*.gpk 的大资源（本来就无名）
   · 补字典能拿到的增量极低（实测：FileNames.list 16.8 万条新路径只换来 3,398 命中，且 100% 是 .nxs）
   · 按名撞库 0 命中 = 「名字未知」，不是「资源不存在」（本轮第二次踩这个坑）
```

### 建议换一个索引形态：**位置-内容索引**（而不是继续扩名字字典）

```
每条记录：容器 + 行号 + 尺寸 + 格式 + 内容指纹 + 视觉特征 + 可推导的上下文
用途：
  ① 按「像什么」检索（比如「竖版、透明底、有 alpha、2048 级、是 sprite 图集」）
  ② 与 atlas/配置里的声明做【配对】（尺寸 + 切片矩形 + alpha 分布）
  ③ 与已知锚点做【邻居推断】（同一容器相邻行的命名族）
```

**立绘那条已经证明这条路可行**：`gres\0000.gpk` r7776/r7783 完全是靠
「邻居法（最近有名行是幻夜神谕）」+「视觉确认」定出来的，跟名字字典无关。
