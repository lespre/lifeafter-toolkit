## ② 修了什么 + 前后证据

### 修 2.1（②线真 bug）`render --polarity` 的 choices 与实现不符

- **改前**：`toolkit_cli.py` 写 `choices=["smooth","steep"]`，而 `render_material_layers.py` 的真实分支是 `smooth / rough / const`（`rough→1-g`、`const→0.5`）。**两头都错**：CLI 放行了一个不存在的值（`steep` 在渲染器里落进 `else` ⇒ 静默等于 smooth，出图完全一样、谁也看不出来），却挡住了真实存在的 `rough`。
- **改后**：choices 改 `["smooth","rough","const"]`；渲染器对未知值 **fail-closed**。
- 证据（实测）：
  - 改前 `render --help` → `--polarity {smooth,steep}`
  - 改后 → `--polarity {smooth,rough,const}`；`--polarity steep` ⇒ `error: argument --polarity: invalid choice: 'steep'`，退出码 **2**
  - 改后 `--polarity rough` 真能跑：`03_执行/30_分析/渲染线_20260928/polarity_rough/` 出 8 张 PNG

### 修 2.2 `render --out` 的 help 被续行符劈坏

- **改前**：`输出目录（默认 03_执行\90_临时ender_out）` —— 源码里那句字符串被一个 `\` 换行（line continuation）劈成两行，`render_out` 的 `r` 被吃掉。
- **改后**：`输出目录（默认 03_执行\90_临时\render_out）`
- 说明：`patch` 工具对「跨源码续行」的匹配会**返回成功但文件没变**（实测三次），最后用字节级替换修的（脚本 `scratch/fix_help.py`）。这条本身值得记进坑表。

### 修 2.3 `render --json -` 的 stdout 不是纯 JSON（契约是假的）

- **改前**：`cmd_render` 调 `mod.main()`，渲染器自己往 **stdout** 打 `LAYERS DONE -> …` + 8 个层名，然后 CLI 又往 stdout 打报告 JSON ⇒ `json.loads(stdout)` **在 char 0 就炸**（我第一版测试就是这么挂的）。
- **改后**：只要调用方要了 JSON，就把被包装模块的 stdout 重定向到 stderr（`contextlib.redirect_stdout(sys.stderr)`），stdout 只剩 JSON。
- 证据：修前测试报 `json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)`；修后同一调用 `json.loads` 成功并断言到 `output_count == 8`。

### 修 2.4（**本次的核心**）`tex`（②-2）→ `render`（②-3）原本接不上

- **改前实测**：
  ```
  tex：5 张 → 03_执行/30_分析/渲染线_20260928/chain_tex（成功 5 / 失败 0）
    产物名 = 00001238.png 00001239.png …（按【行号】命名）
  render … → render 失败：FileNotFoundError: [Errno 2] No such file or directory:
            '…/chain_tex\tex_4011.png'
  ```
  ⇒ `tex` 的输出**没法接着用**，两个命令之间必须人工改名或手写 `_input_manifest.json`。
- **改后**：渲染器新增 `--tex-map 槽位=文件`（可重复）+ `--input-manifest PATH`；CLI `render` 透传。
  ```
  render <mesh> <tex 输出目录> --materials <mtg> \
     --tex-map 4009=00001238.png --tex-map 4010=00001239.png --tex-map 4011=00001240.png \
     --tex-map 4012=00001241.png --tex-map 4013=00001242.png --out …/chain_render
  ```
  退出码 0，8 张 PNG，**与「改名成 tex_XXXX.png 的传统喂法」逐字节一致**：

  | 文件 | 传统喂法 sha16 | 链式喂法 sha16 |
  |---|---|---|
  | BaseColor.png | 0efc8751ca1a72be | 0efc8751ca1a72be |
  | Composite_noSFX.png | d7535b97b2731eef | d7535b97b2731eef |
  | Normal.png | b4f6ec447295fa56 | b4f6ec447295fa56 |
  |（8/8 全等，coverage `{0:186846, 1:22617, 2:2913}` 也一致） | | |

- 顺带把**缺槽位**的报错从 Pillow 的 `FileNotFoundError` 换成可执行的 fail-closed：
  `render 参数/输入不满足：缺少槽位贴图 tex_4009.png, … 三选一：①…②…③--tex-map…`（退出码 2）

### 修 2.5 `render` 的 JSON 报告没有产物清单

- **改前**：报告只有 `out/mesh/tex_dir/materials/polarity/dual/trace` —— 下游要知道出了哪 8 张图只能自己去 glob 输出目录。
- **改后**：报告加 `outputs`（8 条绝对路径）+ `output_count`，并把 `tex_map` / `input_manifest` 回显进去（可追溯是哪些贴图喂的）。退出码改为「有产物才 0」。

### **没有加**的（核过之后判定不该加，写下来免得下一个人再想一遍）

| 候选 | 为什么没加 |
|---|---|

## ⑤ **这次实测推翻了哪些既有说法**

| # | 既有说法（出处） | 实测结论 | 证据 |
|---|---|---|---|
| 5.1 | `RENDER_RULES.md`：「**4012 法线 = GB 通道**」 | ❌ **错**。规范 RGBA 解码下法线的 x,y 在 **R,G**，z 在 B。`render_material_layers.py` 自己的注（「规范 RGBA；原 GB = BGRA 误读」）**才是对的** | 用真实贴图（行 1241 = tex_4012）算：以 (R,G) 为 x,y 时 `|n|` 偏离 1 只有 **0.0044**（平均 |n|=1.0003）；以 (G,B) 为 x,y 时偏离 **0.4085**（平均 |n|=1.4085）。且「用 R,G 算出的 z」与实测 B 的平均绝对差 **0.0182**，反之 **0.4527** |
