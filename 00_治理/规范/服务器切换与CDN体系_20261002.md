## 二、版本号 ↔ 清单的对应关系（★ 关键规律）

```
Documents/update.ini
   [Setting]
   version = 0.<YYMMDD><HHMM截断3位>.<sub版本>
   subversion = 0

实测对照：
   0.260923 164 .1   ←→  npk_version_*_playertest = 20260923_164313_playertest_*   ✓
   0.260923 230 .9   ←→  npk_version_*            = 20260923_230458_release_*      ✓
                         （230452 release / 230458 release_newpc —— 同批构建）

Documents/cloud.json
   combo_patch_dir = "cloudfile_<YYMMDD><HHMM截断3位>/"
   实测：cloudfile_260923164/（PC 测试服）· cloudfile_260923230/（手机正式服）
```

⇒ **判据**：看 `update.ini` 的 version 与 `cloud.json` 的 combo_patch_dir
即可判断该客户端属于**哪条构建线**（release / playertest / …）。

## 三、切服方法 —— 手机端（★ 已实测成功 ✓）

### 3.1 开关 = 一个 1 字节标记文件

```
Documents/download_playertest_patch     内容 = "1"（严格 1 字节）
```

**证据**：
- PC 测试服客户端（`E:\mrzh`）有该文件（1 B，内容 `1`）；手机正式服**没有** ✗
- 手机端补上它 + 改版本文件后重启 ⇒ **客户端立刻改为请求 playertest 清单** ✓
- logcat 实录：`https://g66.update.netease.com:443/pl/npk_version_android4_playertest` → 200 ✓
  并开始下载 `20260929_171236_playertest_android_script.py314.lc.overlay3.*.npk` ✓

### 3.2 完整步骤（★ 版本值必须取【本 tier】的，不能拿 PC 的值给手机）

```
★ 取值原则（2026-10-02 实测踩坑）：
    手机端 playertest 的 tag = 从 npk_version_android4_playertest 的 version 算
       version = 20260923_121822_playertest_android ⇒ tag = 【260923121】
       ⇒ update.ini: version = 0.260923121.1 · cloud.json: cloudfile_260923121/
    ✗ 曾用 PC 的 260923164 ⇒ 客户端报 【E116 版本信息检查失败】✗
    ✅ 换成手机自己的 260923121 ⇒ 通过 ✓ 能进游戏 ✓
    ⇒ 直接用工具算：python 切服与CDN.py gen --tier android --line playertest --out <dir>

目录：/sdcard/Android/data/com.netease.mrzh/files/netease/g66/

① 备份（8 个文件）到客户端内 _backup_before_switch/
   ② 写 update.ini    →  version = 0.260923121.1 / subversion = 0      （手机实测值 ✓）
   ③ 写 cloud.json    →  "combo_patch_dir":"cloudfile_260923121/"       （手机实测值 ✓）
   ④ 新建 download_playertest_patch（内容 "1"，1 字节）★ 开关
   ⑤ 重启客户端：am force-stop com.netease.mrzh
                 am start -a android.intent.action.MAIN -c android.intent.category.LAUNCHER \
                          -n com.netease.mrzh/com.netease.ntunisdk.external.protocol.ProtocolLauncher
      （注意：`monkey` 在雷电里不存在 ✗；`LauncherAlias*` 是别名、直接 -n 会报不存在 ✗）
   ⑥ 登录（人工 ✓ 账号不代填）
   ⑦ 验证见 3.3

### 3.2b 实测结果（2026-10-02 ✓）

```
✅ 生效：能进游戏 ✓ · logcat 里 npk_version_android4_playertest → 200 ✓
✗ 但资源集不变：Documents 仍 43G / 172 包（与切前一致）

## 四、切服方法 —— PC 端（那个"优化助手"的做法，逆向所得）

```
★ launcher_conf 不是开关 ✗（PC 正式服与测试服的该文件【完全一致】= 实测 diff 为空）
   launcher_conf = 单字节 XOR 0xFA 的 JSON，字段仅 version / cleanup / exe
   ⇒ 它只是启动器的"跑哪个 exe + 清理列表"

★ 该工具实际做的事 = 【把目标服的补丁集下载并覆盖到客户端】✓（不是改一个字段）
   它的字符串证据：XorCrypt decrypt/encrypt launcher_conf · ServerLabel · switchVerButton ·
   SwitchVersion · ConfirmSwitch · 5 个 npk_version_newpc4* URL · use_mrzh_launcher=1 ·
   taskkill /F /IM + start "" "<exe>"（先杀进程再启动）
```

⇒ **PC 上"切服"= 换一套补丁文件**；**手机上"切服"= 那个 1 字节标记**（机制不同，别混）。

## 六、风险与合规（必须知道）

```
· 改客户端文件（§3）属于【修改客户端】，违反用户协议 ⇒ 存在封号风险
   —— 风险落在操作者自己的账号上
· 但性质说明：只是【版本/补丁选择】，不修改游戏逻辑、不是作弊工具
· 可回滚 ✓（§3.4）· 不影响服务端 ✓
· 【纯只读】的部分（取清单 / 监控版本）无此风险 ✓ —— 那是服务端公开内容
```
