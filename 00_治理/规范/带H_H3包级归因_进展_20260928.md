## 二、H-3 本轮做了什么

### 2.1 第一版失败：家族粒度选错（0 / 214）

```
错误做法：把本地资源的【目录全路径】当家族
  character/players2021/b_f_2011        ← 细粒度（具体资源目录）
  25_plants / 26_yaojingmijing          ← building_01.gpk 里的家族名
而服务端包名给的是【粗粒度前缀】：
  res/character/players2021 · res/ui · res/model/bigworld
⇒ 粒度差好几级，join 全不中
```

### 2.2 修正：改成【前缀匹配】（175 / 210 命中）

```
包名 res/ui/huodong_icon.layers.1.257.npk
  → 去掉 res/ 与 .layers.*.npk ⇒ 前缀 ui/huodong_icon
本地资源 ui/huodong_icon/xxx/yyy.png
  → 逐级前缀 ui / ui/huodong_icon / … 命中 ⇒ 归因成功

实测：741 个变更/新增包 → 210 个前缀 → 175 个能在本地找到有名行
      2,300,843 行里前缀命中 940,816 行（41%）
```

**产出**：`03_执行/30_分析/包级归因_20260928/归因_前缀匹配.json`

**样例：**
```
character/players2021  → character_08.gpk(37139) · character_07.gpk(34673) · character_05.gpk(21627)
model/bigworld         → model_01.gpk(15388) · model_02.gpk(2426)

scene_bw/pve_new       → scene_bw_05.gpk(14635)

```

### 2.3 试过并失败的：邻近法给【增量包的无名行】标族

```
想法：gres\0000.gpk（热更增量包，54,292 行 / 45,742 无名）的行序 ≈ 下载顺序，
      用前后最近有名行的前缀给无名行标族 ⇒ 就能给立绘这种「无名但有位置」的资源一个族。

实测：失败。理由清楚 ——
```

**★ 但这个「失败」吐出了更硬的证据（见 2.4）。**

## 四、H-3 还没解决的（诚实说）

```
❌ 「本地【哪些行】是新的」—— 仍不可得
   理由：本地只有一份快照，没有旧版本对照；服务端清单只到包级。
   要解决只有两条路：
     ① 攒版本快照（每次热更后跑 H-2 冻结，下次就能 diff 出「新增了哪些行」）
     ② 运行时挂钩（唯一能到 100%，但需要调试器，见 NeoXResearch 那条线）

❌ 175/210 里落空的那 35 个前缀
   多半是「该族在本地全无名」或「该包没下载到本地」——但这两个原因现在分不开
   （因为分不开 ⇒ 按铁律不许下「本地没有」的结论）
```
