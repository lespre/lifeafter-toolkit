# 资源定位速查（2D 图 / 图标 / 贴图）

> 新会话接手时先读这一页，不要重新摸索哈希规则和容器格式。

## 三条命令搞定

```bash
# PE（安卓测试服）
python la.py pe check                                    # 覆盖率 96.80%
python la.py pe resolve ui/item_icon/icon_b_m_3399001_b   # → ('ui/item_icon/icon_b_m_3399001_b.ktx', '0003.gpk', 4364)
python la.py pe export  "ui/item_icon/icon_b_m_3399001_b" -o out.png

# PC（PC 测试服）
python la.py pc check                                    # 覆盖率 95.93%
python la.py pc resolve ui/item_icon/icon_b_m_3399001_b

# npk 图标图库（按图反查）
python la.py npk query <某张png>
python la.py npk query --id 000230BBBC56C5DD
```

## 口径（已定证）

| 项 | 值 |
|---|---|
| 哈希 | `fid = murmur3_x86_32(path, 0x77777777) << 32 \| murmur3_x86_32(path, 0x66666666)` |
| 路径写法 | `/` 必须换成 `\`，全小写，无前导斜杠 |
| PE 扩展名 | `.ktx`（DDS 内容） |
| PC 扩展名 | `.bc7`（BC7 DDS），另有 `.png` / `.jpg` / `.atlas` / `.json` / `.plist` |
| 兜底顺序 | 精确 → 换扩展 → 换档位 `_b`/`_s` → 同名跨目录 |

同一条路径换扩展名就是另一个客户端的落点，**不需要两套哈希**。

## 三条硬规矩

1. **查 PE 索引要用 `fid` 列，不要只搜 `name`** —— 56% 的行没有名字，只按名字搜会得出「客户端没有」的假结论。
2. **`pe全量索引.py build` 会清空名字列** —— 跑完必须接 `refill_pe_names.py` / `refill_names_by_fid.py`。
3. **判「有没有」先验 oracle** —— 拿一张确认存在的图跑通链路，再对目标下结论。

## 现在还剩的缺口（不是定位问题）

- PE 缺 123 张、PC 缺 157 张 —— 都是**客户端未下发**（如 `icon_bag_f_3317001` 连 PC 文件名清单里都没有）
- 核芯特技图标两边命名体系不同：PE `other_icon/jinghejineng/icon_X`，PC `font_icon/icon_new/icon_X_new`
- `item_icon.layers.*.npk` 的 id **不是路径哈希**（试过 28 种写法、5 种映射、4096 个 seed 全 0），只能按图 dHash 匹配
