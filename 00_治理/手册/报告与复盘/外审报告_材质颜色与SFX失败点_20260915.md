## 0. 一句话现状

有一套**源数据驱动的管线**（绑定 c159 → MtlIdx → 材质 c159 → 参数/贴图 → GLB/网页），
数据链是直证的；但**从"源数据"到"屏幕像素"的最后一跳（材质公式 + 特效渲染）全部是我自己拍的近似**，

## 1. 数据链逐环节置信度（**不得整体称为"已直证"**）

| 环节 | 置信度 | 依据 |
|---|---|---|
| SubMesh → index range | **high** | mesh sub 表累计 vc/fc |
| 记录 → MtlIdx → 绑定材质名 | **high** | 绑定 c159 记录内直读（`0a02<u32>0c01<名>`） |
| 记录顺序 ↔ 子网格序 | medium-high | 单枪与名后缀一致；双枪以两族构成印证 |
| MtlIdx → shader | medium | 按材质表顺序；槽位结构直证前不升 high |
| 材质引用了哪些槽（t_/u_ 名单） | **high** | c159_pair 槽位引用组 |
| **槽名 → 贴图路径归属** | **heuristic（未闭环）** | 按基色串切段 + 语义规则；**不得写成已闭环** |
| 参数名/类型/值/字节偏移 | **high** | c159_pair 槽位引用组解析（工具已验证） |
| 参数在 shader 中的用途 | **unproven** | 未追到实际常量读取/运算/分支 |
| fx 挂点 4×4 矩阵 | **high** | 绑定内 16f，对齐偏移经"对角线=1.0"反求 |
| SFX 节点/颜色/缩放/时序轨道 | **high** | .sfx XML 直读 |
| SFX 颜色 4 分量**顺序** | **unproven** | 分量数已证（全 4）；顺序无独立证据 |
| SFX 贴图 name→物理条目 | **candidate（仅实验模式）** | 内容特征匹配，非直证 |
| 源 cube 物理条目 | **unresolved** | 沿路径未找到（不等于不存在） |

## 2. 我的实现（最后一跳，问题都在这）

### 2.1 材质：three.js MeshPhysicalMaterial（自拟，非源公式）

- **几何**：`.mesh` → 自写 GLB 导出（顶点/UV 与源 bit-exact）
- **贴图**：项目规范 BC7→RGBA 解码（`dds_rgba_canonical`）
- **材质**：`MeshStandardMaterial`（Sub0）/ `MeshPhysicalMaterial`（晶体子网格）
- **我做的映射（可能全错的关键点，请重点看这里）**：
  1. `color` ← 直接乘 `u_base_color`（例：010 晶体件乘 (0.12,0.40,0.51)）→ **基色贴图 × u_base_color**，
     但我**不知道 u_base_color 在源 shader 里是"乘算/替换/仅给无贴图分支用"** `[未证]`
  2. `metalness` ← `u_crystal_metallic`（010=0.75）；`roughness` ← `u_crystal_roughness`（010=0.12）
  3. `transmission/thickness/ior` ← **我自己定的 0.35/0.25/1.45**（源里**根本没有**这三个量）`[未证]`
  4. `emissive` ← `u_subsurface_color`，`emissiveIntensity` ← `u_emissive_strength`
  5. `envMapIntensity` ← 全局 1.0 × `u_cube_brightness`
  6. **环境光照 = 我程序化生成的"摄影棚"IBL，不是源 cube**（`qiangpi.cube` / `car_studio01.cube` /
     `fashion_qiangpi.cube` 的**物理条目未映射**，路径已知但取不到文件）`[未证]`
  7. **`pbr_weapon` / `pbr_default` / `pbr_crystal` 的 DXBC 公式完全没实现**——所以：
     源里靠 shader 做的（菲涅尔银白刃缘、参数图通道语义、晶体的反射/折射/焦散采样、
     自发光模式 EMISSIVE_MODE、CUSTOMIZED_IBL）**在我这里全部缺失或被我用三件套（metalness/roughness/transmission）替代**
- **结果**：枪体偏蓝/灰、看不出源里的冰蓝+银白+金层次。用户判定"颜色全错"。

### 2.2 SFX：我写的 sprite 适配器（`assets/weapon_skin_sfx_adapter.js`）

- **源**：`fx_skin_1003_010_zs_02.sfx`（83,327 B，GBK XML `FxGroup`，sha16 `bc3a874b70893946`）
- **已解析（源直读）**：20 节点（8 Sprite / 5 ParticleSystem / 3 Model / 3 Dummy / 1 ParticleRes），
  每节点的 `PosOffset` / `FxStartTime` / `FxLifeSpan` / `Radius` / `BlendMode` / `Texture`，
  以及 **`ColorFrame`（=(A,R,G,B) 关键帧）/ `TrackScale` / `SmoothStart/StopFrame` / 粒子参数曲线**。
- **我的实现**：对每个 Sprite/ParticleSystem 建一个 `THREE.Sprite`（加法混合），
  在源轨道上采样颜色/缩放/alpha 并驱动 `color/opacity/scale`；贴图用"候选集"（见下）。
- **我做的、可疑的近似**：
  1. **尺寸**：`scale = Radius × TrackScale × 0.035`（0.035 是我拍的常数 `[未证]`）
  2. **位置**：源节点 `PosOffset` 绝大多数是 `(0,0,0)`，且全树**没有位置轨道**（标签统计已核）→
     我把所有 sprite 放在**武器主件网格几何中心**（Sub0 包围盒中心 (0, 0.254, 1.445)）→ 表现为"一团光"
  3. **挂点**：绑定 c159 里有 `fx_idle_01`/`muzzle_fire` 等绑定的 **16-float 4×4 挂点矩阵**，
     我两次都没把偏移取准（手读候选 (-0.15,0.38,2.44) 也不可靠）→ `[未证]`
  4. **贴图**：源里 11 个 `Texture` 名 → 我按"贴图池内容特征"配了**候选**物理 DDS（1 个名字 1 个候选），
     **不是直证映射**；`lightning*.spr`（精灵表）也当普通贴图用了 `[未证]`
  5. **ParticleSystem 的发射行为完全没做**：源里 `EmissionRadius/EmissionRadius2/SpriteScale/SpriteHeight/
     HWRatio/Gravity/Max-MinSpriteVelocity/RotDegreeSpeed/EmissionDirDegree/NoiseStrength/X-Y-ZDirDisturb` 共 13+ 条曲线
     → 这是特效"形状/扩散/拖尾感"的来源，我**一条都没用**（只当静态 sprite 用）
  6. **Model 节点（3 个：M_m_聚气lv / H_模型星点05 / H_m_cai_1）未做**（需要它们自己的模型资源）
  7. **BlendMode 语义未证**：我按 {0=普通, 2/5/8=加法} 处理 `[未证]`
  8. **挂点/时序与实机未对照**：没有实机截图锚点
- **结果**：一团发光贴在枪中间，用户判定"SFX 全错、就是一坨"。

## 6. 本轮自查迭代的新发现（2026-09-15 追加，请 GPT 一并判）

### 6.1 槽名↔贴图**直证**（取代原来的启发式）
`c159_pair.py` 的**槽位引用组**给出每个材质**真正引用哪些槽**（源直读）：

| 材质 | 引用槽位（源直读） |
|---|---|
| `pbr_weapon`（010 Sub0） | `Tex0` `ParamMap` `t_surfacemap` `NormalMap` `t_custom_ibl` `u_cube_brightness` |
| `pbr_crystal`（010 Sub1/2） | `Tex0` `t_basecolor` `NormalMap` `DetailMap` `t_caustic_tex` `t_custom_ibl` `t_reflection_tex` `t_refraction_tex` + 全套 `u_*` |

**两个重要推论**：
1. **`u_base_color` 只出现在晶体材质组**，武器材质组（group 1）里**没有**它 —— 我现在确实是"Sub0 不带参数、Sub1/2 才带"，
   所以"用 u_base_color 乘武器基色"这类错误**在我实现里不存在**。颜色的错要向别处找。
2. `t_custom_ibl` = 那张 cube（`qiangpi.cube` / `car_studio01.cube`）——即**源材质的 IBL 是逐材质的**，
   不同材质用不同 cube（010 武器用 qiangpi、晶体用 car_studio01；029 还有 fashion_qiangpi）。
   我现在用**全局程序化摄影棚**代替 → **三个材质的环境反射被拉平成同一个**，这是色偏的头号嫌疑。
3. 交叉验证：武器组槽序 `[Tex0, ParamMap, t_surfacemap, NormalMap, t_custom_ibl]`
   ↔ 文件路径顺序 `[001a, 001m, 001s_m, 001n, qiangpi.cube]` **逐位一致** ✓
