## 4. 证据分级（写在 manifest / 报告里的口径）

- `declared_path_direct`：源声明路径按名命中容器（如两把皮肤的三张 cube、`refraction_envmap_3`）。
- `content_class_signature` / `declared_name_semantic_candidate`：按**解码后的内容类**（color / param(B≡1) / normal / surf_r / surf_gb）或声明名语义定槽 —— **候选级**，不是像素直证。
- `ordered_1to1_candidate_high`：区块内 1:1 有序配对（候选级）。
- `source_not_sampled`：源 shader 根本不采样该槽（如 `t_reflection_tex`）。
- `unresolved` / `not_shipped`：拿不到或源侧没发布 —— **一律保持无效，不用别的资源顶替**。

### 8.2 「光效颜色」疑点：`ColorKeyFrame` 四分量顺序**很可能读反了**（Lead 分析，待修）

## 22. 口径收紧（2026-09-20，用户/GPT 纠正后采纳）

### 22.1 可以封闭的（保留）
在确认 `H16[i] ↔ entry[i]` 同序关系、且样本 `checksum→path` 唯一的前提下，现有反例足以证明：
> **H16 不是仅由路径决定的确定性哈希，也不是仅由解码载荷内容决定的确定性哈希；因此不能从目标路径或源 checksum 直接计算 H16 查条目。**

⇒ **不再试 xxh3 / CityHash / SpookyHash / FarmHash / SipHash / CRC64**（H16 数学形式这条线到此为止）。

### 22.2 不能推出的（撤回）

- ~~"H16 就是构建期随机分配的 ID"~~ —— 同路径同内容却不同 H16，仍可能是 **`path/content + entry/container salt`**、**每条目 GUID/nonce/IV**、**上级资产引用的内部 ID**、或**独立排序表（并非与 entry 同序）**。
- ~~"剩余贴图本机没有"~~ —— "全载荷 md5 ≠ 源 tga checksum" 只能证明：**扫描范围内不存在与源资产原始字节完全相同的载荷**，**不能排除源 tga 已被转码为匿名 DDS 存在于本机**。
