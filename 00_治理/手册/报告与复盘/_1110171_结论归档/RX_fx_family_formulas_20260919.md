## 3. ★ 三个问题的答案（证据 = PS 反汇编行号；变体 `9053b046_7c6dc86e_d11_blob1.dxbc.asm`）

**先给槽位映射**（cbuffer 0 = per-material UBO；同一 asm 的成员表 L12-100 ✓）：

| uniform | offset | cbuffer 槽 |
|---|---|---|
| `u_emissivecolor` | 48 | **cb0[3].xyz** |
| `u_emissive_power` | 380 | cb0[23].w |
| **`u_emissive_highlight_intensity`** | 384 | **cb0[24].x** |
| `u_emissive_grey_intensity` | 388 | cb0[24].y |
| `u_emissive_mix` | 392 | cb0[24].z |
| `u_mask_intensity` | 396 | cb0[24].w |
| `u_mask_power` | 400 | cb0[25].x |
| **`u_overall_opacity`** | 404 | **cb0[25].y** |
| `u_emissive_desaturate` | 408 | cb0[25].z |
| `u_softparticle` | 412 | cb0[26].x **[unused]** |
| **`u_depth_bias`** | 416 | cb0[26].z **[unused]** |
（另：`u_mask01_channel`@420 · `u_mask01_tilling_x/y`@428/432 · `u_mask01_offset_x/y`@436/440 ⇒ **该族 shader 内确实有 mask01 的 tilling/offset** ✓，但 **1110177 的 .sfx 未声明其值** ⇒ 仍属"无源值不覆盖" ✓）

### ① `u_emissivecolor` 如何进入最终颜色 —— **加法项，且先被 highlight_intensity 缩放**
```
L405-408  r2 = pow( max(r1, 0.0001), cb0[23].w )            ; 幂曲线（u_emissive_power）
L409      mul  r2.xyz, r2.xyzx, cb0[24].xxxx                ; ★ × u_emissive_highlight_intensity
L410      mad  r1.xyz, r1.xyzx, cb0[24].yyyy, -r2.xyzx      ; 与 u_emissive_grey_intensity 的差
L411      mad  r1.xyz, cb0[24].zzzz, r1.xyzx, r2.xyzx        ; × u_emissive_mix 混合
L412-414  dp3 亮度(0.300/0.590/0.110) → 泛灰 + × u_emissive_desaturate
L415      mad  r1.xyz, r1.xyzx, cb0[3].xyzx, r3.xyzx        ; ★ × u_emissivecolor.xyz（+ r3）
L421-424  r0.xyz = f(cb0[2].xyz, cb0[16].w, 开关 cb0[16].z)  ; 漫反射/溶解边色项
L425      add  o0.xyz, r0.xyzx, r1.xyzx                     ; ★★ 最终色 = 漫反射项 + 自发光项（**ADD**）
```
**⇒ 答**：**是"加法"进入最终色**（`o0.xyz = r0 + r1` ✓），**但不是"直接相加"**：`u_emissivecolor` 在 L415 才乘上，之前**先经 `u_emissive_highlight_intensity`(L409) → `u_emissive_grey_intensity`/`u_emissive_mix`(L410-411) → 亮度泛灰/`u_emissive_desaturate`(L412-414)** 处理 ⇒ **最小正确实现 = 加法 + 至少乘 `u_emissivecolor`；若要完整，需按上式带上 4 个系数** ✓

### ② `u_overall_opacity` —— **只乘 alpha，不乘亮度**
```
L400      mul     r0.w, r0.w, cb0[25].x     ; × u_mask_power
L403      mul_sat r0.x, r0.x, cb0[24].w     ; × u_mask_intensity
L404      mul     o0.w, r0.x, cb0[25].y     ; ★ o0.w(alpha) = 掩码项 × u_overall_opacity
```
颜色路径（L405-425）中**没有任何** `cb0[25].y` 引用 ✓ ⇒ **`u_overall_opacity` 是乘到输出 alpha（`o0.w`）上的**，不参与颜色 ✓

### ③ `u_depth_bias` —— 在本族 shader 内**不被消费**，单位 unresolved
`u_depth_bias` 在**该族全部 4 个 asm（2 pipe × VS/PS）**里都只有**声明行 1 处、指令体 0 处**，且带 **`[unused]`** 标记；batch 变体同理（`u_depth_bias_batch[4]` @5968 `[unused]`）⇒ **不是 shader 内计算** ⇒ 只能由**引擎的渲染状态/深度偏移**消费 ⇒ **单位与作用阶段 = unresolved** ✓（但**已排除**"在 shader 里做深度偏移"这条 ✗）
**`TransparentMode` 的语义线索**（只能给线索，不给定论）：`.sfx` 里 `TransparentMode` 取 **0/2/5**；对应地在 PS 里能看到**开关式分支**：`L423 ne r0.w, cb0[16].z, l(0)` + `L424 and r0.xyz, r0.xyzx, r0.wwww`（用一个 cb 系数**整体开关**漫反射项）⇒ 提示不同 `TransparentMode` 会走不同编译分支/开关；**映射表仍未定证** ⇒ 标 unresolved ✓

## 4. 给 chain-auditor 的"最保守可做/不可做"清单

**只看关键帧就能接（无需公式）** ✓
- `u_emissivecolor`（ColorKeyFrame）→ 直接作为颜色
- `u_overall_opacity`（FloatKeyFrame）→ **乘 alpha**（现已有公式证据 ✓，L404）
- `u_emissive_highlight_intensity`（FloatKeyFrame）→ 乘到颜色项（L409 ✓）
- 节点生命周期 `FxLifeSpan` / `StartTime` → 做时间窗
**必须有公式/系数才能接（现在**已有**）** ✓
- 完整自发光复合（`power`/`grey_intensity`/`mix`/`desaturate`）⇒ 公式已给（§3①）
- `u_dissolve_amount`（FloatKeyFrame）⇒ 需 L390-402 的 smoothstep 与 `u_dissolve_smooth`@256；本轮未逐行展开 ⇒ **建议由 chain-auditor 直接照 §3 的窗口继续追**
**明确不可做** ✗
- `u_depth_bias`（shader 内不消费；单位 unresolved）⇒ **不要**用它做 z 偏移；如要深度效果只能用引擎等价（`RenderBias` 节点属性）并标"近似"
- 贴图槽绑定（`tex_candidates_provenance.json` 是 `bound:false`）⇒ 不填
- UV tilling/offset（.sfx 未声明）⇒ 不填（虽然 shader 有 `u_mask01_tilling/offset`，但**每节点无源值**）
- 混合模式：**加法项（emissive）已有证据** ✓，但**整体混合**（ADD vs ALPHA blending）由引擎 `TransparentMode`/渲染状态决定，**未定证** ⇒ 不要断言
