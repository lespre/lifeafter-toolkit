## 二、优点（值得保持的方法）

1. **数值判据优先**：完整性自检（`f/v ≥ 1.5`）、bbox 三重校验、按高度切片贴合 —— 这些替代了"看着对不对"，可靠得多。
2. **主数据只读 + 产物分离**：`E:\mrzh` 全程只读，所有写入限定在 RUN / wiki，没有污染原始包。
3. **诚实标注**：未决项标 `unresolved`、认领标"候选级"、近似标授权码，没有硬编。
4. **全流程脚本化**：解包、渲染、截图、诊断、打包、健康检查都是脚本，可复跑。
5. **工具链复用**：定位链（murmur3 fid 反查 + bbox 校验）、渲染链（GLB 导出 + viewer）都被后续任务直接复用。
6. **坑当场写进技能**：每次踩坑立刻 `skill_manage` 记下来，跨会话不丢。

## 三、不足（诚实清单，按代价排序）

### ★★★ 1. 认领环节靠猜，来回轮次太多
头饰 / 背包 / 位置各绕了 5~10 轮。根因：**没先要锚点就动手**——技能里明明写着"先向用户要一件已上线外观的实机截图当锚点，没锚点就跑识别=纯猜"，但一开始就跳过了。

### ★★★ 2. 全局坐标假设没有先校准，反复搞错
- **Y 轴**：一度认定"源 Y 大 = 头"，实际相反，导致头饰/背包全错位
- **Z 轴**：把"源 Z 负"当成背后，实际是人形正面 —— 背包贴到了胸前
- 教训：**朝向/坐标这类全局假设，必须先在已知正确的对象上校准**（用衣服剖面、头饰同侧关系交叉验证）

### ★★★ 3. 用视觉判断代替数值判断
多次依赖 vision 看截图，而 vision 判断前后/朝向并不可靠，导致误判后继续错。
正解：**几何量测（分层 X 宽度、bbox、连通块）比看图可靠**。

### ★★ 4. 交付面塞了太多实验版本
中间给用户看过 A/B/C 多版本、三档高度、四组候选，用户直接说"太乱了"。
正解：**交付面只放定版**；需要用户指认时才临时建对照页，指认完立即撤。

### ★★ 5. 在用户已否定的方向上继续试
"自绘头骨"用户明确说不要之后还试了多轮。**用户说不做就是不做**，别换个参数再来。

### ★★ 6. 脚本碎片化
为每个子任务写一个新脚本（`qj_*.py` 累计几十个），没有统一入口、没有参数化。
后果：同类问题换个对象就要重写一遍。

### ★ 7. 页面改动缺自动化回归
多次出现"改完页面 `loaded=0`"（JS 语法错、字段名不匹配），要到截图才发现。
正解：**改完立即跑 `node --check` + 无头加载断言**（后期已加，但前面几轮是白耗）。

### ★ 8. 打断用户节奏
反复让用户"选一下""看一眼"，本可自己判断的（如按顶点最多取高模）也去问，违背了"能自己判断的自己判断"。

## 四、可复用的教训（已固化）

1. **先要锚点/参照物，再动手识别**
2. **数值判据 > 视觉判断**（量 bbox、剖面、连通块，别靠看图）
3. **全局假设先在已知正确对象上校准**（坐标方向、尺度单位）
4. **交付面只放定版**，实验产物定版即删
5. **改完立即可验证**（语法检查 + 加载断言 + 像素/字节兜底）
6. **工具先设计统一入口再写**，避免一个任务一个脚本
7. **用户否定的方向立刻停**
8. **认领不出唯一解时，交付"候选 + 用户指认"，不要宣称已定案**
