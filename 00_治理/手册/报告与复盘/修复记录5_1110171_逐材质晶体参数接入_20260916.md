## 二、缺陷 13：逐材质晶体源参数从未接入

**发现**：
- `03拆包产物/_known_loop/c159_params_001265.json` 存有**逐 prim 完整的晶体参数**（索引 0–6 对应 7 个 prim），
  与外审报告 §3.4 表格**逐值一致**：
  | prim | u_base_color | u_crystal_color | u_crystal_metallic |
  |---|---|---|---|
  | 1 | [0.1216,0.3961,0.5059] | [0.4314,0.3333,0.4824] | 1.0 |
  | 2 | [0.1216,0.3961,0.5059] | [0.2471,0.0157,0.2627] | 1.0 |
  | 3 | [0.1216,0.3961,0.5059] | [0,0.3647,1.0] | 0.75 |
  | 5 | [0.1098,0.3961,0.502] | [0,0.2118,0.8] | 1.0 |
  | 6 | [0.1216,0.3961,0.5059] | [0.0039,0,0.6745] | 0.75 |
- 但 `viewer.json` 的 `material_layers.per_submesh` 是**空数组 `[]`** → viewer L300 只能退回通用默认
  `[0.1216,0.3961,0.5059]` / `[0,0,1]`
- 主链的晶体材质只是 `MeshStandardMaterial({map:t_basecolor})` —— **真正的三次 lerp 公式只存在于
  `?neoxView=C_base` 诊断 shader 里**，而那个 shader 把 **prim5 的常量硬编码**套用到全部晶体
  （与「各材质用自己的 c159 块，非套用 prim5」相悖）

**即：逐材质源参数一直在磁盘上，却从未进入渲染。**

**修复（两步）**

1. **manifest**：为 5 个 crystal prim 写入 `crystal_params`（`u_base_color` / `u_crystal_color` /
   `u_crystal_metallic` / `u_crystal_specular` / `u_detail_*`），附 `provenance` 指向
   `c159_params_001265.json[prim].params`。
2. **viewer**：新增晶体源公式注入（链式调用 `onBeforeCompile`，不覆盖 IBL 注入）：

```glsl
vec3  q_T  = diffuseColor.rgb;                              // = map(t_basecolor) 采样值
float q_mm = clamp(texture2D(uCrystalMask, vMapUv).r, 0.0, 1.0);   // Tex0 = 001b_m
vec3  q_A  = mix(q_T, q_T * uCrystalColor, q_mm);
vec3  q_B  = mix(uBaseColor, q_T * uCrystalColor, q_mm);    // d = q_mm（DetailMap 缺失的降级分支）
diffuseColor.rgb = mix(q_A, q_B, q_mm);
```

注入点选 `#include <map_fragment>` 之后；标识符一律 `q_` 前缀（吸取同日 `__` 保留名事故教训）；
`metalness` 逐 prim 取 `crystal_params.u_crystal_metallic`。

## 四、仍未解决（如实登记）

1. **p95 0.853 vs 参考 0.579**：整体仍偏亮约一档。曝光项 `u_env_day2night_exposure`
   （asm 549 / cb1[239].x）是**场景级逐帧常量**，静态包内不存在（外审 §三 列为运行时缺项）。
   项目明令**禁止**用 exposure/toneMapping 拟合参考图，故停在此处。
2. **`DetailMap` 仍是降级渲染**（`d = q_mm`）。外审 §3.3 的内容匹配候选 `src_tex/gpk_1229.png`
   为 `content-match / candidate-high`，无显式指针，按纪律未升级为直证。
3. **晶体仍缺 3 类源资源**：`t_caustic_tex` / `t_refraction_tex` / `t_reflection_tex`。
4. **缺陷 14（未修）**：`__ladderL1`（约 L2442）注入 `uDiagColor` 却未声明该 uniform，仅影响诊断路径。
5. `u_pattern_2u_dye` / `u_pearl_*`：名字确在 `render_1003_010/_pipes_catalog_weapon.json`
   与 `stats_variant_constants.py` 中出现，但**不在 `_known_loop/dxbc_cb_groups.json` 的 30 个材质级变量里**，
   其数值与绑定路径未验证 → unresolved。
6. 诊断 shader（`?neoxView=C_base`）仍**硬编码 prim5 常量**；主链已逐 prim 正确，
   诊断路径未同步（属遗留，影响面小）。
