### 2.3 并发与失败标注

- **锁**：`home_snapshot()` 全程持有 `threading.Lock`，同一时刻只有一个线程做全量采集；其余等待后直接吃缓存结果（多标签/多设备共享一次计算）。
- **失败如实标注**：接口返回 `failed_items = {read_errors, unreadable_fields, index_status_from}`，
  `unreadable_fields` 由 `collect()` 的 None/空值**机械推导**（本次为空数组）；采集抛异常则回 `500 home_snapshot_failed` 并带原始异常，**不返回编造数值**。
- `gen_home.FAILS` 原本是模块级累加列表，服务端反复调用会越攒越长 ⇒ 现在 `collect()` 开头清空（单次语义正确，`main()` 行为不变）。

### 4.2 `/api/coverage`（`workbench_status.html` 报 404）

**先查清事实（有实测，不是猜）**：

| 问题 | 结论 | 依据 |
|---|---|---|
| 跑不跑 | **当时没跑** | `netstat` 里 8770 无监听 |
| 听哪个端口 | **127.0.0.1:8770**（`--host/--port` 可改） | `api/server.py:231` argparse 默认值 |

**采用的方案**：在 8765 里**只读转发**（不复制它的取数逻辑）：

- 后端在跑 ⇒ `/api/coverage` 200，与直连 8770 **内容等价**（除每次都会变的 `generated` 字段，以及新增的 `proxied_by` 标记）；
- 后端没跑 ⇒ **503 + 中文明确报错**：
  `{"error":"工作台后端未连接","detail":"目标 http://127.0.0.1:8770/api/coverage：URLError … 启动方式：在 04_站点/web 目录执行 python -m api.server --host 127.0.0.1 --port 8770","code":"workbench_api_unavailable"}`
  （错误体刻意用**字符串 `error` + `detail`** 的形状——`assets/workbench_client.js` 就是这么读的，用默认 `{code,message}` 对象页面只会显示「[object Object]」）。
- 页面实测（无头 Chrome，后端未起）：**无未捕获 JS 异常**，顶部红色提示变成
  「无法从 Workbench API 取数：**工作台后端未连接**：目标 … 启动方式：… 本轮不允许静默回退 legacy board / historical 数据」，
  并回退到 `data/workbench_status.js` 的构建期静态快照（原文案与降级逻辑不变）。

**没有改 `workbench_status.html`**：本任务硬约束是「不改其他页面（含 workbench*）」，而且「未连接」提示与静态快照回退还原本就存在；
转发方案已经让 404 变成「有数据 / 有中文说明」两态。仍然建议（未做，需你点头）：加一个 `启动工作台接口(8770).bat`，或把它并进统一入口。
