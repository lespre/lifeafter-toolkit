# 折射链去向更正与最终结论（2026-09-17）

## ⚠️ 一、更正我上一条错误结论

**曾报**：「折射计算是死代码 —— L492 之后 `r8.xyz` 从未被读取」。

**错因**：我的追踪脚本扫描范围写成 `range(491, min(len(lines), 660))`，
而**反汇编共 998 行**，读取点在第 992 行 —— **被截断的扫描范围导致误判**。

**实况**（全量扫描）：`r8.xyz` 在 492 之后**被读取**，且恰好一处。

> 教训：这类"从未被读取/死代码"的断言，必须**声明扫描范围**或做全量扫描；截断范围得出的否定结论不可靠。

## 二、折射结果的真实去向（`3f7860cd` / `d982f18f`，998 行 / 同语义）

```asm
992  dp3_sat r0.x, l(0.300000, 0.590000, 0.110000, 0.000000), r8.xyzx   // Rec.601 亮度 → sat
995  mul     o0.w, r0.x, cb0[186].x                                     // × cb0[186].x
991  mul     o0.xyz, r0.xyzx, cb1[266].xxxx
```

| 项 | 值 |
|---|---|
| `o0.w` | `sat(luma(折射结果)) × cb0[186].x` |
| `cb0[186].x`（3f 变体） | ≡ `cb0[6].x` → 偏移 **96** → **`u_alpha_mtl`** |
| 亮度权重 | `(0.300, 0.590, 0.110)` = Rec.601 |

**结论：折射链驱动的是输出 alpha `o0.w` —— 即晶体的不透明度。**

### 这与既有口径的关系

用户此前定版：「源 Blend/Depth/折射状态恢复前，晶体一律按不透明渲染并标 `incomplete`，不得自行开启透明」。
该决定**依然正确**，因为此时链路仍不完整（缺 LOD 与曝光常数）。但**现在机制已明**：

- 晶体透明度**不是**来自 `t_basecolor.a`（那是粗糙度），
  **而是**来自 `折射图 × 球面UV × 折射调制 → 亮度 → × u_alpha_mtl`。
- 换言之：之前 `incomplete` 标注所对应的「折射层」，其**真实作用是 alpha**，不是颜色。

## 三、折射链完整规格（已复原部分）

```glsl
// 1) 球面等距柱状 UV（L480）
vec2 uvR = vec2(h.x * 0.159155 + 0.5, h.y * 0.318310 + 0.5);   // 1/(2π), 1/π ；h 由方向向量经多项式 asin 得出

// 2) 采样（L481）—— LOD = u_refraction_mipmap (cb0[11].z)
vec4 s = textureLod(t_refraction_tex, uvR, u_refraction_mipmap);

// 3) 折射调制（L482-484）
vec3 d = vec3(2.0*s.z*s.x*s.x, 2.0*s.z*s.y*s.y, 2.0*s.x*s.z*s.z);

// 4) 对比度/亮度/颜色（L485-490）
float k = clamp(d.x * (2.0*u_refraction_contrast + 1.0) - u_refraction_contrast, 0.0, 1.0)
          * u_refraction_brightness;
vec3  refraction = d * (k * u_refraction_color);

// 5) 掩码与曝光（L491-492）
refraction *= r3_w;                    // r3.w 掩码（来源未追完）
refraction /= cb1[266].x;              // 场景曝光

// 6) 亮度 → 输出 alpha（L992/995）
o0.w = clamp(dot(vec3(0.300,0.590,0.110), refraction), 0.0, 1.0) * u_alpha_mtl;
```

## 四、可用性（结论未变：仍不能接）

| 依赖 | 状态 |
|---|---|
| `t_refraction_tex` ← `gpk_1230` | ✅ 唯一合格候选（真实 alpha std 75.0，已重解含 alpha） |
| `u_refraction_color` / `contrast` / `brightness` / `rotation` | ✅ c159 有 |
| `u_alpha_mtl` | ✅ c159 有（偏移 96） |
| **`u_refraction_mipmap`** | ❌ **全部可得数据中都没有取值** —— 已穷举验证：7 个 c159 文件 + `dxbc_buffer_definitions*.json`（135 条目、**0 个带 value**） |
| `cb1[266].x` 场景曝光 | ❌ 运行时场景常量 |
| `r3.w` 掩码来源 | ⚠ 未追完 |

**→ 仍不接入。** 缺的两个量（LOD、曝光）会让实现退化为自拟参数；且新发现表明接入它会**改变 alpha**，
而 alpha 口径是用户明确定过的 —— 属于不能擅自变更的项。

## 五、本轮净产出

1. **更正**了一条错误结论（死代码误判），并记录成方法学教训。
2. **定位折射链的真实作用**：不是颜色，而是**晶体输出 alpha**（`o0.w`），
   系数为 `u_alpha_mtl` + Rec.601 亮度。
3. **穷举验证** `u_refraction_mipmap` 静态不可得（7 个 c159 + 135 条 buffer 定义，0 个取值）。
4. 折射链公式的**可复原部分已完整落盘**（`折射层公式复原规格_20260917.md` 的补充）。
5. 交叉确认：`u_rotate_angle` 仅用于 IBL 方向（L532 sincos），与折射链无关 —— 报告「两条链分离」成立。

## 六、由此更新的判断

晶体"辉光/通透感"缺口 = **折射链未实现**，而该链：
- **公式已复原**（除两个常数）
- **资产唯一合格的那张在手**（`gpk_1230`）
- **但它的作用是 alpha，不是发光** → 即使实现，也不会让晶体"更亮"，
  而是让晶体**呈现半透明**

→ **参考图的辉光目前仍无解释来源**：既不来自 `u_emissive_*`（本皮肤无此参数），
也不来自折射链（那是 alpha），也不来自 `t_caustic_tex`（候选 alpha std 0.3 不合格）。
**剩余最可能的来源是显示链（bloom）** —— 属项目已登记的运行时未解项。
